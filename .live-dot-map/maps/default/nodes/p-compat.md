# 多 Agent 与小白验收

## 背景
技术底座和内部 RC 通过自动测试后，还必须在真实客户端和真实用户路径中验证正式兼容。

## 当时考虑
不能用模拟脚本或逐步提示词代替真实生命周期；需要分别验证 Claude Code、Kimi Code、CodeBuddy/WorkBuddy、普通用户首次打开、地图可读性和完整协作闭环。

## 结果
Codex 与 Kimi 有真实或受引导闭环证据，CodeBuddy Code CLI 有真实 MCP 写回证据；Claude、WorkBuddy 桌面端、普通小白全流程和 FS 直连多地图人工覆盖仍未全部闭环。

## 当前意义
这是协作与分发支线的当前问题节点，与主线人工验收中相互关联但不合并。

## 下一步
按客户端生命周期逐一验收，记录真实失败；完成首次地图可读性和普通用户全流程后，才能升级为正式兼容和公开发布依据。
