# bug1 切换项目agent不知道？

**现象**：安装版画布中切换到「ui设计 html」项目并新建地图「第四轮排查」之后，Agent（MCP stdio）仍把上一轮回答建立在切换前的错误项目（壁纸制作）上，造成“读错项目/读不到新地图”的错觉。

**根因（两层）**：
1. 执行层：Agent 判定“当前项目”用了过期的画布标签标题（信息源滞后），未以 MCP 实时结果为准——MCP 实际可正确列出新地图（map_list 返回 active=map-mt421fju）。
2. 架构层（真实缺口）：画布切换项目只更新 HTTP 桥会话的 projectRoot/activeMap；独立启动的 stdio Agent 桥在进程启动时锁定项目根（会话 cwd），**没有接收画布“切项目”事件的机制**。
   - 同项目内切地图：Agent 每次按 per-project 的 active-map 文件解析 → 地图级实时、正确。
   - 跨项目切换：无共享状态、无通知 → Agent 不知道画布换了项目根，只能停留在自身绑定的根。

**影响**：人机双开多项目时，Agent 调用不带 mapKey 的上下文工具可能停留在自己的项目根；跨项目场景易错位。

**修复方向**：
1. 项目根状态共享：桥维护全局“当前项目”指针（如 last-project / 状态文件），stdio Agent 工具每次解析该项目根（agent-kit 已有 projectIdForRoot 思路）。
2. Agent 侧约定：多项目并行时显式携带 mapKey（地图级已支持），项目级由宿主在启动时以画布当前项目为根。
3. 验收：画布切项目后，Agent 的工具调用不再依赖会话 cwd，全部跟随画布当前项目。
