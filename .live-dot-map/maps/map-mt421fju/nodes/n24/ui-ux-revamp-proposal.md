## 问题一：人机笔迹区分机制

### 1. 现状痛点诊断
- **视觉灾难**：当前实现是通过直接注入 `<mark>` 标签，将整篇/整段文字刷成**刺眼的荧光黄背景**。这在视觉人机工效学中是致命的——大面积的高饱和度背景色会直接摧毁字体的层级、对比度与行距呼吸感，产生严重的视疲劳（Visual Fatigue）。
- **侵入性污染**：将 `<mark>` 这种物理 HTML 标签直接写入底层的 `.md` 文件中，用户用 VS Code 或 Obsidian 打开时，满眼都是 HTML 标签，破坏了 Markdown 的纯净性。

### 2. 用户想法剖析
> “用户提出：是不是只在人类写的开头和结尾用比较醒目的黄色亮框给它框起来，A写的用紫色框框起来？或者只标人类的？如果全黄观感太差。”

- **专业评估**：
  - “只标首尾”的思路方向是正确的（**降低视觉干扰面积**），但如果在纯文本排版里直接画两个括号或首尾打方框，会造成段落阅读的严重视觉断裂（Visual Clutter）。
  - 最符合现代顶级协作工具（如 Google Docs 协作标记、GitKraken/GitHub 审阅模式、Notion 评论区）的做法，是**从「行内荧光涂抹」升级为「块级发丝标记（Gutter Trace / Side Accent）」**。

### 3. 设计师推荐方案：发丝级侧边指示线 + 隐式作者透视

```
[常规显示态 — 极简干净，100% 舒适白底黑字]
------------------------------------------------------------
这是由人类提出并补充的问题分析。
段落文字保持标准深灰排版，阅读体验纯粹舒适。
------------------------------------------------------------

[审阅/透视模式 或 鼠标 Hover 段落时]
┌── [👤 人类 · 14:20] ─────────────────────────────────────
│ 这是由人类提出并补充的问题分析。
│ 左侧是一条 2.5px 宽的琥珀金发丝竖线，段落具有微弱的底色呼应。
└──────────────────────────────────────────────────────────

┌── [🤖 Agent · 自动沉淀] ─────────────────────────────────
│ 这是由 Agent 自动整理生成的解决方案步骤。
│ 左侧是一条 2.5px 宽的柔和紫靛色发丝竖线。
└──────────────────────────────────────────────────────────
```

- **视觉呈现细节**：
  1. **人类字迹（Human）**：采用 `--brand-amber`（琥珀金/暖金发丝边框，`#D97706` 极细 2.5px 竖线，微淡背景底色 `rgba(245, 158, 11, 0.04)`）。不再使用荧光黄，高贵克制。
  2. **Agent 字迹（Agent）**：采用 `--brand-indigo`（紫靛色发丝竖线，`#6366F1` 极细 2.5px 竖线，微淡背景底色 `rgba(99, 102, 241, 0.03)`）。
  3. **非侵入式存储**：不再给 Markdown 文本强塞 `<mark>` 标签。建议在段落开头使用轻量 Markdown 格式化规范（例如标准的 Blockquote 或者隐藏元数据注解 `<!-- by:human -->`），保持外部编辑器打开时干干净净。

## 问题二：编辑面板（Dock/Drawer）的 UI/UX 系统级诊断与重构

当前面板暴露出明显的设计缺陷：空间浪费严重、视觉层级混乱、操作按钮粗糙突兀。

### 痛点逐项诊断与优化方案

| 区域 | 当前现状与痛点 | 专业设计师重构方案 |
| :--- | :--- | :--- |
| **1. 行号槽 (1 2 3)** | 宽度高达 46px，还带冗余边框与边距，强行占据宝贵横向宽度；节点笔记并非代码调试，强行放 IDE 行号显得本末倒置。 | **极简化或默认隐藏**：<br>① 默认关闭行号，使文本拥有居中、舒展的阅读版心（类似 Typora/Notion）；<br>② 若保留，压缩为 20px 宽度的超轻淡灰色无边框数字，仅作轻量辅助。 |
| **2. 资料包与侧边栏** | 右侧「资料包」硬编码死占 230px 宽，不可折叠、不可伸缩，严重压缩主编辑视界；而面板本身的宽度缩放反而显得多余。 | **可折叠抽屉分栏 (Collapsible Split Rail)**：<br>① 资料包侧栏增加一键折叠按钮（快捷键或右上角折叠图标），折叠后退为 32px 极窄图标竖条，编辑区扩宽至 100%；<br>② 展开时提供平滑宽度微调，默认宽度自适应为 180px。 |
| **3. 底栏「标记/取消」** | 文案语义极其模糊（不知道是标记选中文字还是某种开关），右边排着 3 个简陋彩色圆圈，像未完成的原型。 | **移除底栏杂项，改用「浮动选区工具条」**：<br>底栏不应当作调色盘使用。文字标记应是“选中文字时”自然在光标上方微量浮出胶囊菜单（Floating Menu：[重点] [便签] [复制]），不选时不打扰。 |
| **4. 右下角保存按钮** | 亮紫色高饱和实心大矩形方块（`--accent`），色彩刺眼不高级，缺乏品牌内涵，充满“粗糙表单提交”既视感。 | **重构为 Linear 级深墨色精致按钮**：<br>① 采用深墨黑/冷岩深灰（`--ink` / `#18181B`）微弧倒角（6px），配合 1px 发丝微亮边与轻微投影；<br>② 支持未修改时**幽灵态/禁用态**，内容变更时沉稳点亮；或者集成自动防抖保存，底栏左侧显示轻量文字 `✓ 已自动保存`，无需用户每次焦虑地狂按 Ctrl+S。 |

## 问题三：节点「已解决」状态设计与 Agent 上下文精准减负机制

用户敏锐地提出了一个极为关键的系统设计问题：**已解决的问题节点，如何收纳？如何防止 Agent 被垃圾历史淹没？**

### 1. 概念解耦：状态（Status） vs 归档（Archive）
- **未解决/进行中（Active）**：正常在画布中显示，作为当前思考网络的核心节点。
- **已解决（Resolved）**：
  - **视觉呈现**：节点不再维持高对比度，变为**低饱和度极淡灰底**，左上角或右侧增加一个精致的微型绿色对勾徽章（`✓`）；连线变淡为灰色细线。
  - **交互方式**：节点右键菜单增加一键「标为已解决」；详情面板头部也有一个 Checkbox 或状态下拉。
- **已归档（Archived）**：节点从主画布隐藏，移入“已归档折叠箱”或收纳抽屉中，点击地图菜单可查看。

### 2. 彻底解决 Agent 上下文膨胀（Context Pollution）
当前 Agent 每次对话一开始会扫描全局所有 Markdown，当项目进行到几十个节点时，Prompt 注入数万 Token，不仅浪费额度，更会导致 Agent 抓不住重点。

**分级加载模型（Tiered Context Protocol）**：
1. **活跃节点（Active）**：Agent 默认注入全部上下文（结构 + 正文 + 待办）。
2. **已解决节点（Resolved）**：**禁止注入正文大文本！** Agent 扫描时只注入极轻量的一行摘要（例如：`- [已解决] n1: bug1 切换项目agent不知道 (结论: 增加当前项目全局指针)`）。如果 Agent 明确需要复查证据，再通过特定工具按需读取。
3. **已归档节点（Archived）**：默认 100% 排除在上下文之外，零 Token 消耗。

## 问题四：编辑打字全篇变黄 Bug 根因与根治

### 1. 为什么打一个字会导致前面文字全部变黄？
- **代码根因剖析**：
  在 `app.html` 的 `showMdEditor` 与 `renderMirror` 逻辑中：
  - 系统使用 `mdParseMarks(raw)` 解析文本中的 `<mark>` 标签。
  - 一旦用户或工具无意中将大段文本包裹在 `<mark>...</mark>` 中，整个段落的逻辑范围被判定为同一标记区块。
  - 编辑器使用的是“双层镜像（Mirror + Textarea）”架构：底下的 Textarea 文字完全透明，上层的 Mirror 层负责用 `<span class="hl">` 上色。当你在一段文字中敲入新字符时，由于字符落在了未闭合的 `<mark>` 作用域内，或者 `mdDiffSpan` 将未保存的修改合并进了已有的高亮区间中，导致高亮区间瞬间蔓延至整个前置文本。

### 2. 根治方案
1. **格式物理隔离**：彻底废止向文件本体直写 `<mark>` 物理标签的逻辑。
2. **纯文本 Markdown 解析器收口**：主文档保存纯净的标准 Markdown。
3. **基于 Diff 的只读视图标记**：人机协作痕迹完全由 Bridge 端的 Git Commit 或元数据 Session 追踪计算，仅在前端作为只读装饰图层渲染，绝不动态反向修改用户的文本标签结构。

## 是否引入新组件与设计规范升级建议

### 1. 拒绝盲目引入重型全家桶（如 AntD / Element / MUI）
- **理由**：活点地图是一个追求**丝滑画布、毫秒级响应、极简克制**的本地生产力工具。引入几十 MB 的重型 UI 库会导致页面体积膨胀、样式冲突、失去轻盈原生感。

### 2. 建议引入的轻量现代设计资产（Headless & Fine-tuned）
1. **Lucide Icons 图标体系**：
   - 替换当前混乱的 Emoji（🟡🟣🔵）和手绘粗糙 SVG；
   - 采用标准 14px / 16px 发丝粗细（Stroke 1.5px）的专业级矢量图标（如折叠侧边栏 `PanelRightClose`、对勾 `CheckCircle2`、作者图标 `User` / `Bot`）。
2. **浮动气泡工具条（Floating Selection Bar）**：
   - 参考 Notion / Medium 交互，封装一个 30 行原生 JS 的小巧选区浮层，选中文本时平滑淡入。
3. **微交互分段控制器（Segmented Control）**：
   - 统一顶部的「编辑 / 预览」、右侧的「展开 / 折叠」，采用类似 macOS / iOS 的平滑滑块切换效果。
4. **高级色彩令牌微调**：
   - 引入暗夜墨黑 `--ink-solid: #18181B`；
   - 引入低饱和高级紫蓝 `--accent-refined: oklch(58% 0.12 280)`，消除生硬廉价感。
