# mcp和桥的含义

 MCP 的本来样子

   你说的对，每个 MCP 都是这个形态：CLI 拉起一个本地进程，双方用 stdin/stdout 传 JSON 消息。所
   以「传话筒」不是新发明的一层东西——那个进程一直都在，区别在于它肚子里装什么。

   上下文里到底有什么

   我（agent）的上下文里只有两样东西，改造前后完全一样：

   1. 工具清单：25 个工具的名字+一句话说明+参数格式，几 KB 文本。会话启动时问一次。
   2. 每次调用的参数和返回值：比如「帮我读 n17 的文档」→ 一次调用的输入+结果文本。

   那 450KB 是程序代码，跑在你的机器上干活用的，就像你装的微信 exe 不会进聊天窗口一样，它从来不
   进我的上下文。

   所以改完轻在哪

   不是上下文轻了（上下文本来就没胖），是工程上轻了：

   ┌──────────────────┬───────────────────────────────────┬──────────────────┐
   │                  │ 现在                              │ 改完后           │
   ├──────────────────┼───────────────────────────────────┼──────────────────┤
   │ livedot.mjs 文件 │ 450KB，含全部逻辑                 │ 几十行，只转发   │
   ├──────────────────┼───────────────────────────────────┼──────────────────┤
   │ 工具逻辑存几份   │ 两份（桥 exe 一份、这个文件一份） │ 一份（只在桥里） │
   ├──────────────────┼───────────────────────────────────┼──────────────────┤
   │ 更新逻辑         │ 换文件 + 重开会话                 │ 桥重启即生效     │
   ├──────────────────┼───────────────────────────────────┼──────────────────┤
   │ 写地图的进程     │ 两个（桥 + 每个 MCP 进程）        │ 一个（只有桥）   │
   └──────────────────┴───────────────────────────────────┴──────────────────┘
