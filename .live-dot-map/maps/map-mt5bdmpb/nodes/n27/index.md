## 主代理复核结论（2026-08-24）

原问题成立：不应继续以网页富文本编辑器作为正式成稿入口。现行专利业务办理系统对发明新申请的权利要求书、说明书、说明书附图和说明书摘要应以 CNIPA 数据标准的 XML 文件提交；2026 年页面已取消这几类文件的 PDF/Word 直接上传。可行流程改为：以本地正式成稿为来源制作四份 Word 源文件 → 使用 CNIPA WORD 转 XML 编辑器生成 XML 压缩包 → 用该工具生成/查看预览 PDF 并逐页核对 → 在新申请“上传”入口提交 XML 压缩包。现有 `main.pdf` 只作为版式和内容对照，不作为主申请文件上传。

本轮确认：此前网页编辑器中的正文/附图未形成可复用的正式文件提交包，且切换页面后内容不再显示；本地完整 PDF 与 LaTeX 源文件仍在，未丢失。请求书著录信息须在重新创建申请时重新填写或由已保存草稿恢复后核对；不在确认 XML 预览通过前重复手工录入正文。

待办：检查本机是否已具备 Microsoft Word 与 CNIPA WORD 转 XML 编辑器；目前未发现可直接调用的 Word 程序。不得为绕过工具要求而改用 PDF 直接提交。

## 实施结果：Word 版式校准与提交策略（2026-08-25）

### 回答：应当选“合规结构 + 原 PDF 的视觉标准”，不是二选一

原 main.pdf 是很好的视觉对照：字体层级、正文密度、标题位置和阅读节奏都值得保留；它不能直接作为当前电子申请的主申请文件上传。官方 Word→XML 五书结构才是提交格式约束。因此，不应为“看起来像 PDF”而破坏五书分节，也不应因为套进模板就接受正文松散、页数膨胀的 Word 版。

已将正式内容按官方五书模板生成“版式校准版”，仅压缩正文层，不改官方页眉、页脚、分节、连续页码、摘要附图独立页和既有技术内容：

- 正文由 12 磅、1.5 倍行距校准为 10.5 磅、1.25 倍行距；标题仍为黑体层级。
- Word 本地渲染由 24 页收敛为 22 页，与原 PDF 总页数一致。
- 实际逐页查看了摘要、权利要求书首页、说明书首页、流程图页和产品截图页：正文未溢出、权利要求悬挂关系正常、流程图编号与箭头可读、图 7—9 保持未裁切。
- 新文件：docs/patent-tex/CNIPA-XML提交包/五书源文件-人机共享记忆自愈索引与按需下探-版式校准版.docx；
  本地对照渲染：docs/patent-tex/tmp/cnipa-word-build/五书源文件-Word渲染-v4.pdf。

### 尚未通过的最后门槛

既有正式源稿当前被 WPS 占用，无法安全覆盖；因此尚未把校准版替换为最终转换源，也尚未生成或验收 CNIPA XML 预览。不能把“本地 Word/PDF 通过”误报成“可提交”。

下一步仅需关闭正在打开的该五书 DOCX（不必关闭其他 WPS 文档），然后：

1. 以校准版覆盖正式五书源；
2. 在 CNIPA WORD 转 XML 编辑器中生成 XML 压缩包；
3. 查看该工具的 XML 预览 PDF，逐页核对；
4. 仅在 XML 预览通过后，上传 XML 压缩包。上传和正式提交仍须在操作当时再次确认。

### 后续固定验收方式

以后修改时先渲染 Word，用原 PDF 只做视觉回归对照；真正的最终门槛是 CNIPA XML 工具生成的预览。不再制作或上传单独的“提交 PDF”。

## 实施更新：权利要求书重复编号修复（2026-08-25）

### 问题定位

官方 XML 预览中每项权利要求左侧会按 `num="1"—"10"` 自动生成编号；原 XML 的权利要求正文又手写了“1.、2. … 10.”，因此出现两套编号。说明书、摘要和附图没有发现同类可见重复。

### 实际修改

- 修改生成脚本 `docs/patent-tex/tmp/cnipa-word-build/build_cnipa_five_book.py`：权利要求正文不再写外层数字，由 CNIPA XML 转换器生成唯一编号。
- 用脚本重新生成并覆盖正式源：`docs/patent-tex/CNIPA-XML提交包/五书源文件-人机共享记忆自愈索引与按需下探.docx`；版式校准版仍保留。
- 对现有正式 XML 包的 `100001/100001.xml` 做同样的最小修复：仅移除 10 个权利要求正文开头的手写外层数字，保留 `num="1"—"10"` 和全部技术正文；原重复编号压缩包保存在 `五书源文件-人机共享记忆自愈索引与按需下探-重复编号备份.zip`。
- 重新生成可上传包：`docs/patent-tex/CNIPA-XML提交包/五书源文件-人机共享记忆自愈索引与按需下探.zip`。

### 验证

- 正式 DOCX 的 `word/document.xml`：手写外层编号匹配数为 0。
- 正式 XML 的 10 个外层 `claim-text` 均以权利要求正文开头，不再以“数字+句点”开头；内层技术特征编号“（1）—（4）”保留。
- XML 包仍包含 100001—100005 五书目录及全部附图资源；10 项权利要求保留。
- Word 的 XML 检查可作为结构验证；官方预览仍是最终视觉保险，但本轮本地官方预览服务对新包返回“服务器异常”，因此不把该服务错误误报为预览通过。重复编号本身已由源 DOCX、XML 文本断言和包内容核验确认修复。

### 当前状态

重复编号修复已完成，正式 XML 压缩包可继续作为上传包使用；尚未点击 CNIPA 最终提交。提交前仍需在页面上复核申请人信息、费减备案序列号和上传包，最终提交动作另行确认。
