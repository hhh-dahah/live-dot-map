 ● 计划已写好。先把核心结论给你（细节和论文引用都在计划里）:

   1. 「人脑记忆本质也是索引」——你的直觉有理论背书。 海马体索引理论（1986）说海马体不存记忆本体，只存指向皮层记忆单元、
   互相关联的索引；HippoRAG(NeurIPS'24）把它工程化后多跳推理提升约 20%。所以 JSON 索引层的方向没有理论缺陷。真正的缺陷
   是：人脑索引有生命周期（睡眠巩固、衰减遗忘、重要性标记），而 map.json 只有写入。

   2. 百行级不是地图容量，是读取预算。 小图全读，中图（数百节点）按「投影规则」读：主路线链 + 全部 pending + 停滞路线 +
   各路线一行摘要。读全局 ≠ 读全部——前额叶工作记忆本来就只有几个槽位，投影就是工作记忆。

   3. 打分 vs 三态：对，该加。 score(0–100）就是杏仁核的「重要性标签」,Generative Agents 当年就是靠 importance 评分让记
   忆可排序的。三态保留做粗分类，score 做细粒度，Agent 提建议时按分排序。

   4. 创新能力不是格式给的，是循环给的。 专家能创新而 RAG 不能，因为专家知识是重组过的结构，RAG 是孤立片段——你的地图恰
   好就是重组结构，这是它优于向量知识库的根本点。缺的是协议循环：更新 → 投影读全局 → 找结构空隙（停滞线/低分区/可迁移的
   高分方案）→ 提案 → 尝试 → 回写。JSON 完全承载得住，不需要换底层。

   5. 睡眠巩固有现成的产品化先例:Letta 的 sleep-time compute、Claude Code 的 AutoDream、Google 的 30 分钟巩固 cron。对
   应到你就是协议里加一个「整理例程」：合并冗余、归档停滞低分线、绿线沉淀 skill、重算路线摘要。最小实现，不用新基础设施
   。

   执行计划：map-json 升 v1.1(score/archived/updatedAt)→ 协议加三节（投影读取/整理例程/创新循环）→ 画布渲染 score 徽标
   （零依赖小改）→ 壁纸项目真实打分做狗粮验证。明确不做：向量库、KG 引擎、自动删除（只有可恢复的归档）。
