# 活点地图 v2 可靠协同人工体验验收

这份清单给不懂程序的测试者使用。测试者只需要打开画布、点击按钮、向自己平时使用的 Agent 发自然语言消息；不要打开终端，不要编辑 JSON。

## 开始前

1. 用一个可以随时清空的测试项目文件夹，不使用真实项目。
2. 优先从内部 RC 安装器启动并打开正式画布；确认右下角不是“降级模式”，而是“桥接 · 已保存”。如果是降级模式，先停止测试并记录截图。
3. 确认关闭并重新打开画布后仍使用同一桥接 origin，不应因为随机端口变化丢失会话或草稿。
4. 先不要让 Agent 初始化地图，观察首次引导是否给出“空白开始 / 简单示例 / 让 Agent 初始化我的项目地图”。

## 必测闭环

### 人的标注 → Agent 读取

1. 在画布空白处添加一条标注，写下一个只有你知道的业务要求。
2. 等状态变成“已保存”，关闭再打开画布，确认标注仍在。
3. 在已连接的 Agent 中发送：

   > 请先读取活点地图，先告诉我你看到的人类新标注 ID 和原文，再开始做任何修改。

4. Agent 的第一段摘要必须出现标注 ID；没有出现就记录为失败，不要替 Agent 猜测或手动确认。
5. 继续让 Agent 创建一个目标或问题节点，观察画布是否在 2 秒左右出现，且看得出“Agent 探索”来源。结果和证据应进入关联 Markdown，不应新建活跃里程碑。

### 并发与撤销

1. 画布改名，等“已保存”；点击撤销，等“已保存”；关闭再打开，确认撤销结果仍在。
2. 让 Agent 同时改另一个对象，确认两边都保留。
3. 让人和 Agent 同时改同一字段，确认出现“冲突”，不能静默覆盖。

### 多地图与草稿隔离

1. 创建第二张地图，确认创建完成后仍停留在原地图；主动切换后画布显示第二张地图。
2. 在 A 图和 B 图分别新增一个节点，来回切换并关闭重开，确认对象、Markdown 和草稿不串图。
3. 让 Agent 读取上下文，确认只出现当前 `projectHandle + mapKey` 下的非归档对象；其他地图、备份、WAL、归档对象和项目根目录无关 Markdown 不得混入。

### 归档、恢复与清除边界

1. 人归档一个节点、补充 Markdown 和附件，确认对象从画布和默认上下文消失，但仍可恢复。
2. 让 Agent 对另一个对象执行 archive，再由人恢复；确认两者权限一致、ID/坐标/Markdown 保留。
3. 在测试副本上验证永久清除必须经过人的二次确认或系统 30 天任务；回收站失败时必须保留归档，不能直接永久删除。不要在真实项目上做清除测试。

### 资料包与附件

1. 新建节点和路线后，确认主文档路径分别为 `nodes/<id>/index.md`、`routes/<id>/index.md`，对象改名不会移动主文档。
2. 新建、改名、归档、恢复补充 Markdown，确认 etag 冲突会提示而不是覆盖另一方内容。
3. 上传 PNG/JPEG/WEBP/GIF/PDF/DOCX/SVG，确认使用二进制流、大小和文件头校验；SVG 下载时不会在页面内执行。非法扩展名、MIME、路径穿越、symlink/junction 和超过 20 MiB 的文件必须拒绝。

### 旧数据与本机能力

1. 打开含旧 `result` 节点或 milestone 字段的测试副本，确认可以加载；旧字段原样保留但不触发新语义，新建节点只能是 goal/problem。
2. 触发 `suggest_milestone` 时，确认返回 `FEATURE_RETIRED`，不能悄悄创建对象。
3. 打开外部编辑器或另存为时，确认界面使用 Bridge 登记的 opaque editor id；用户看不到、也不能输入任意可执行路径，Agent 不能调用该能力。

### 失败状态

在保存过程中断开本地桥或暂时让项目不可写。画布必须显示错误/离线/冲突，而不是绿色“已保存”。恢复后确认修改能继续保存，或给出明确恢复按钮。

## 测试者只回答这些问题

- 我是否知道当前修改已经保存？
- 我是否知道 Agent 是否真的读到了我的新标注？
- 我能否一眼看出哪些大节点由人创建、哪些由 Agent 探索创建？
- 初始地图是否只表达目标、问题和待判断事项，没有变成目录树？
- 我切换地图后，是否仍然只看到当前地图的资料？
- 我是否能安全归档、恢复对象，并清楚永久清除需要额外确认？
- 出错时我是否知道下一步怎么做，而不是只能找程序员？

## 记录方式

每个问题只记录四项：操作、看到的结果、期望结果、截图/录屏路径。不要在本文件里直接改方案；统一追加到 `README.md` 或同目录的新问题文件，开发方案写回 `docs/plans/8-12上线plan.md`，执行证据写回 `implement.md`。
