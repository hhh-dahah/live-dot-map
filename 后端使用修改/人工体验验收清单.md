# 活点地图 v2 人工体验验收

这份清单给不懂程序的测试者使用。测试者只需要打开画布、点击按钮、向自己平时使用的 Agent 发自然语言消息；不要打开终端，不要编辑 JSON。

## 开始前

1. 用一个可以随时删除的测试项目文件夹。
2. 优先从内部 RC 安装器启动并打开正式画布；确认右下角不是“降级模式”，而是“桥接 · 已保存”。如果是降级模式，先停止测试并记录截图。
3. 先不要让 Agent 初始化地图，观察首次引导是否给出“空白开始 / 简单示例 / 让 Agent 初始化我的项目地图”。

## 必测闭环

### 人的标注 → Agent 读取

1. 在画布空白处添加一条标注，写下一个只有你知道的业务要求。
2. 等状态变成“已保存”，关闭再打开画布，确认标注仍在。
3. 在已连接的 Agent 中发送：

   > 请先读取活点地图，先告诉我你看到的人类新标注 ID 和原文，再开始做任何修改。

4. Agent 的第一段摘要必须出现标注 ID；没有出现就记录为失败，不要替 Agent 猜测或手动确认。
5. 继续让 Agent 创建一个节点或大节点里程碑，观察画布是否在 2 秒左右出现，且看得出“Agent 探索”来源。

### 并发与撤销

1. 画布改名，等“已保存”；点击撤销，等“已保存”；关闭再打开，确认撤销结果仍在。
2. 让 Agent 同时改另一个对象，确认两边都保留。
3. 让人和 Agent 同时改同一字段，确认出现“冲突”，不能静默覆盖。

### 失败状态

在保存过程中断开本地桥或暂时让项目不可写。画布必须显示错误/离线/冲突，而不是绿色“已保存”。恢复后确认修改能继续保存，或给出明确恢复按钮。

## 测试者只回答这些问题

- 我是否知道当前修改已经保存？
- 我是否知道 Agent 是否真的读到了我的新标注？
- 我能否一眼看出哪些大节点由人创建、哪些由 Agent 探索创建？
- 初始地图是否只表达目标、阶段和待判断事项，没有变成目录树？
- 出错时我是否知道下一步怎么做，而不是只能找程序员？

## 记录方式

每个问题只记录四项：操作、看到的结果、期望结果、截图/录屏路径。不要在本文件里直接改方案；统一追加到 `README.md` 或同目录的新问题文件，开发方案写回 `docs/plans/8-12上线plan.md`，执行证据写回 `implement.md`。
