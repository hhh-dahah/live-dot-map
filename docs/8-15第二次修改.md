## 记录 01：首次打开画布，新手引导（从一张地图开始）闪现约 1 秒就消失

### 用户动作

安装软件后第一次打开画布（新项目/默认工作区），看到"从一张地图开始"引导出现，还没来得及看就消失了。

### 用户预期

首次使用应该能看清引导内容，自己选择"空白开始 / 看看简单示例 / 让 Agent 初始化我的项目地图"，而不是一闪而过。

### 实际结果

- 引导（三个选项卡片）出现后约 1 秒自动消失，用户反应不过来。
- 引导消失后画布里已经有一个"开始"节点（模板地图）。

### 用户原话

> 第一 我安装软件后 第一个跳出来就是这个新手提示 可我不知道为啥这个 一秒就消失了 我都反应不过来

### 截图路径

- `C:\Users\Thomas\Documents\ShareX\Screenshots\2026-08\chrome_nJMLSexGPi.png`（"从一张地图开始"引导：空白开始 / 看看简单示例 / 让 Agent 初始化我的项目地图，含说明文字）

### 核实情况（根因已定位）

1. **引导显示条件**（app.html L2534-2539）：`boot().then(...)` 后，**仅当桥未激活且 `S.nodes.length === 0`** 才显示"从一张地图开始"。
2. **引导移除条件**（集成代码 `LiveDotApp.load` L2556-2561）：桥加载文档后，**只要 `nodes.length > 0` 就移除引导**（设计意图：已有地图就不该显示首启引导）。
3. **矛盾点**：新项目初始化（`installProject`）用 `agent-kit/map.template.json` 创建地图——**模板自带 1 个"开始"节点 n1**（`nodes=[n1]`、无 edges/anns）。因此首次打开时序为：
   - 页面加载 → 桥尚未激活 → 显示引导（满足显示条件）；
   - 桥初始化完成 → `load(模板地图)` → `nodes.length > 0` → **立即移除引导**。
4. **附带问题**：引导显示条件没有检查 `localStorage.dotmap-guide-seen`——用户选过"空白开始"后刷新，只要地图为空（`S.nodes.length===0`）引导还会再弹。

### 待汇总问题

- [x] P1 首启引导：`load` 移除引导的条件过宽——模板地图（仅 1 节点、0 边、0 标注）不应算"已有地图"；改为"有真实内容才移除"（`nodes.length > 1 || edges.length > 0 || anns.length > 0`）。**（8-15 第三轮已修复：`scripts/build-app.mjs` appIntegration `LiveDotApp.load`；`tests/e2e/bridge-browser.mjs` 增补模板保持/真实内容让位断言，三浏览器通过）**
- [x] P2 引导去重：显示条件补充"未看过引导"检查（`!localStorage.dotmap-guide-seen`），选择任一入口后记录已看；手动入口（菜单"新手引导"）不受影响。**（8-15 第三轮已修复：`app.html` boot().then 条件 + `showFirstMapGuide` 选择入口 seen()；`tests/e2e/first-map-guide.mjs`、`tests/e2e/bridge-browser.mjs` 覆盖）**

> 第三轮补充：首启引导三入口重组为「选择项目…（含最近项目列表与返回）/ 空白开始 / 看看简单示例」，桥模式下"选择项目…"用原生文件夹选择器 + 最近项目；无桥直开仍走浏览器文件夹直连。

## 记录 02：安装后点快捷方式先弹一个"启动器"窗口，无实际用途且与画布功能重复

### 用户动作

安装完成后点击桌面快捷方式，先看到一个"活点地图"小窗口（默认工作区 + "打开其他项目"按钮 + 状态日志），随后才打开浏览器画布。

### 用户预期

双击快捷方式应该像大厂产品一样**直接进入主界面（画布）**，不应出现中间启动弹窗；"打开其他项目"不应与画布内的功能重复、让人迷惑。

### 实际结果

- 快捷方式先弹出启动器窗口（标题"活点地图"：正在打开默认协作画布 / 默认工作区路径 / 打开其他项目 / 状态日志），画布在浏览器中另开。
- 启动器窗口"打开其他项目"与画布左上项目菜单的"选择或切换工作区…"看起来重复，用户不知道该用哪个。

### 用户原话

> 安装完成后 我点击快捷键会显示这个页面 再打开这个地图 可是这个界面没啥用吧 这么一个弹窗 我没见过大厂产品有个这么个弹窗的 而且这里的打开其他项目这个按钮跟画布浏览器的功能重复 用户就会很迷

### 截图路径

- `C:\Users\Thomas\Documents\ShareX\Screenshots\2026-08\LiveDotMapSetup_55ZW8MZ5cc.png`（启动器窗口 OCR：活点地图 / 正在打开默认协作画布。需要时可用本机文件夹选择器切换到其他项目。/ 默认工作区：C:\Users\Thomas\AppData\Local\LiveDotMap\workspace / 打开其他项目 / 状态 / `[22:26:45] 正在准备默认工作区…`、`[22:26:45] 默认协作画布已打开。此窗口可以关闭，画布会继续运行。`）
- `C:\Users\Thomas\Documents\ShareX\Screenshots\2026-08\chrome_WpiH9TBhtz.png`（桥模式 URL `127.0.0.1:1089/app.html?project=C%3...` 下，在画布内点"选择或切换工作区"选 `E:\壁纸制作` 后报错：`没能打开文件夹: An operation that depends on state cached in an interface object was made but the state had changed since it was read from disk.`）

### 核实情况（根因已定位）

1. **启动器窗口的来源**：`installer/winforms/Program.cs` 的 `ProductLauncherForm`（`--open` 参数）。它做的事：确保默认工作区 → 启动本地桥 → 打开带 token 的浏览器画布 URL；"打开其他项目"用原生 `FolderBrowserDialog` 选目录后由桥重新 `serve` 该项目。窗口可关闭，桥继续运行。
2. **"打开其他项目"与画布内功能并不等价（这是迷惑的根源）**：
   - 启动器"打开其他项目"→ 原生选目录 → **桥 serve 新项目（强协作模式保持）** ✓
   - 画布项目菜单"选择或切换工作区…"（`openProjectFolder`）→ **直接走浏览器 File System Access（`attachDir`）** → 画布切换为**浏览器直读模式（降级，无协同保护）**，**完全没有经过桥** ✗
   - 两个入口长得像、行为不同：一个保桥、一个降级——用户必然迷惑。
3. **架构缺口**：桥 `serve` 启动时只 allowlist 启动时传入的那一个项目（`allowedProjectRoots`），没有"会话内切换项目"接口；画布在桥模式下无法自行切换到另一个项目（无法调用本地 exe，浏览器也不能直接选目录交给桥）。因此"打开其他项目"目前只能由启动器窗口完成——去掉窗口前必须先补桥的项目切换能力。
4. **用户实测报错**：桥模式下点"选择或切换工作区"选 `E:\壁纸制作` 报 `state cached ... changed since read from disk`——`E:\壁纸制作` 刚被清理（`.live-dot-map` 移走），浏览器文件夹授权句柄读到磁盘状态已变即抛该 InvalidStateError；叠加"桥模式却走浏览器直读"的路径错配，暴露两个入口语义冲突。
5. **结论**：窗口本身是"起桥 + 原生选项目"的载体；用户不需要弹窗，但项目切换入口必须保留且语义唯一。

### 待汇总问题

- [x] P1 无弹窗启动：`--open` 改为静默后台起桥并打开默认工作区画布，不显示启动器窗口；快捷方式双击直达画布。**（8-15 第三轮已修复：`installer/winforms/Program.cs` `SilentOpenContext` + `ProductLauncherLogic`；`scripts/verify-windows-product-entry.ps1` 断言无窗口、静默退出、last-project 记忆与恢复，通过）**
- [x] P1 画布内项目切换（桥模式）：桥新增"会话内切换项目"接口（认证会话允许打开新目录并重新绑定）；画布项目菜单在桥模式下改走该接口，切换后画布重载到新项目。**（8-15 第三轮已修复：`src/bridge/server.mjs` `/api/v1/projects/open|pick|recent` 会话内切换 + `src/web/bridge-client.ts` switchProject/pickProject/recentProjects/attachProject；`tests/e2e/bridge-browser.mjs` 增补切换重载+已保存+继续写新项目，三浏览器通过）**
- [x] P1 入口唯一化：桥模式下画布内的"选择或切换工作区"不再走浏览器 File System Access 降级路径；浏览器直读仅保留为明确标注的降级/无桥场景。**（8-15 第三轮已修复：项目菜单「工作区▸」桥模式下为 选择其他项目…/最近项目/新建空白地图；抽屉文件夹按钮桥模式改走原生选择器；`attachDir` 捕获 InvalidStateError 提示"文件夹状态已变化"）**
