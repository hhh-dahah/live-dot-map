## 记录 01：安装位置应自动包含产品目录名

### 用户观察

安装器显示“软件安装位置”，当前截图中的路径为：

```text
D:\livedotmap
```

右侧有“更改位置”按钮。

![软件安装位置默认产品目录](8-14第二次测试.assets/01-软件安装位置默认产品目录.png)

### 用户预期

用户在安装器中选择的是“安装到哪个位置”，而不是把产品文件直接散落到磁盘根目录。产品应自动带一个稳定的产品文件夹名，例如：

```text
D:\livedotmap
```

这样用户选择 `D:\` 后，安装器应自动生成 `D:\livedotmap`，而不是把 exe、运行库和其他文件直接写到 `D:\`。

### 当前判断

- 截图中的 `D:\livedotmap` 形态符合“父目录 + 产品目录名”的用户心智。
- 仅凭这一张图还不能确认用户点击“更改位置”并选择 `D:\` 后，安装器是否仍会自动追加 `livedotmap`。
- 也需要确认用户选择一个已有的 `livedotmap` 目录时不会变成重复嵌套的 `D:\livedotmap\livedotmap`。

### 待验证与改进要求

- [ ] 用户选择 `D:\` 后，最终预览路径自动变为 `D:\livedotmap`。
- [ ] 用户选择 `D:\应用` 后，最终预览路径自动变为 `D:\应用\livedotmap`。
- [ ] 用户直接选择已有的 `D:\livedotmap` 时，不重复追加产品目录名。
- [ ] 安装器明确区分“选择父目录”和“最终安装目录”，避免用户误以为会直接占用所选目录。
- [ ] 最终安装路径内的文件保持集中，`D:\` 或用户选择的父目录不出现散落的产品文件。
- [ ] 目录名、开始菜单入口、桌面快捷方式和卸载项使用统一的产品命名。

### 本轮结论

这条更像是需要固化的安装体验规范，而不是截图中已经确认的故障。后续测试优先验证“选择父目录后自动追加产品目录名”和“已有目录不重复嵌套”两个分支。

## 记录 02：安装完成后不应先弹出“选择项目文件夹”窗口

### 用户动作

安装完成后打开产品，看到一个独立窗口，标题为“活点地图”，内容直接要求选择“项目文件夹”，并提供“选择项目文件夹”和“打开画布”。

### 用户预期

安装完成后应先进入正式画布。项目/工作区选择是画布内的一个轻量入口，不应成为产品启动后的阻断弹窗。

参考 DeepSeek Harness：

- 工作区入口位于产品侧栏/画布边角，以小文件夹图标呈现。
- 用户可以点击文件夹入口选择工作区。
- 可以通过“添加工作区”管理多个工作区。
- 没有选择工作区时，产品仍然可以打开、创建地图并连接 Agent。

![安装后启动器要求先选项目](8-14第二次测试.assets/02-安装后启动器要求先选项目.png)

![DeepSeek 工作区入口](8-14第二次测试.assets/03-DeepSeek工作区入口.png)

![DeepSeek 添加工作区](8-14第二次测试.assets/04-DeepSeek添加工作区.png)

### 产品目标

启动顺序应改为：

1. 安装完成后直接打开正式画布。
2. 画布左上角或侧边提供一个克制的工作区/文件夹图标。
3. 用户可添加、切换或移除工作区；工作区状态在画布中可见。
4. 用户暂时不选择工作区时，也可以使用画布、创建地图和接入 Agent。
5. 没有工作区时，地图和节点记录写入产品为用户准备的默认本地目录；用户之后选择项目时，可以明确迁移/关联，而不是静默丢失或覆盖。

### 默认记录目录要求

- 默认目录属于产品数据目录，不应散落到磁盘根目录。
- 默认目录需要显示在工作区入口的帮助信息或设置中，但不阻断首次使用。
- 用户选择真实项目后，新的地图记录默认写入该项目内稳定的 `.live-dot-map/`；已有默认地图必须可继续打开或由用户明确选择迁移。
- Agent 连接不应依赖用户先完成工作区选择；没有工作区时也要能建立产品级连接，待用户选择项目后再绑定项目级地图。

### 待验证与改进要求

- [ ] 安装完成后直接打开正式画布，不再弹出必须先选择项目的阻断窗口。
- [ ] 画布提供一个小文件夹/工作区入口，可以添加和切换工作区。
- [ ] 不选择工作区时仍能创建地图、创建节点和连接 Agent。
- [ ] 无工作区时的 map/node 记录写入稳定的产品默认目录，并在界面可查。
- [ ] 选择工作区后，项目地图写入项目内 `.live-dot-map/`，不覆盖默认地图。
- [ ] 从默认目录切换到项目目录时，迁移/关联动作有明确提示和可恢复备份。
- [ ] 主画布不展示“本地桥”“MCP”“hook”“项目根目录”等实现术语。

### 本轮结论

这是安装完成后的产品入口层级问题，不是单纯把启动器文案改短。正式产品应当“先进入画布，再在画布中选择工作区”；工作区是可选上下文，不能阻断画布和 Agent 的基础能力。

## 记录 03：画布打开后完全无法操作，不能新建节点（P0）

### 用户动作

打开正式画布后，尝试使用顶部“新建节点”工具，并在空白画布区域点击/操作。

### 实际结果

- 画布显示为空白，左上可见地图名称“动态壁纸”，顶部工具栏也正常出现。
- 选择工具显示为激活状态，但用户无法在画布上进行有效操作。
- 新建节点无法生效，核心画布功能不可用。
- 截图中没有可见的错误提示、离线提示或恢复操作，用户无法判断是保存、项目、连接还是画布本身出了问题。

![画布无法新建节点](8-14第二次测试.assets/05-画布无法新建节点.png)

### 严重性

**P0 阻断**。新建节点是产品最基础的画布动作；无法操作时，地图、Markdown、Agent 接入和后续人工测试均没有意义。

### 排查范围

- [ ] 正式安装器 payload 与源码 `app.html` 是否一致，是否打开了错误/旧版本。
- [ ] 产品启动器 → 本地桥 → 浏览器会话是否造成透明遮罩、只读态或事件层失效。
- [ ] 新建节点按钮、画布 pointer/click 事件、工具状态、缩放/平移层是否被错误拦截。
- [ ] 无工作区/默认工作区状态下，是否错误把画布设为不可编辑。
- [ ] 浏览器控制台、桥事件和保存状态是否有未显示给用户的错误。

### 验收要求

- [ ] 在无工作区、默认本地目录和已选项目三种状态下，用户均可新建、移动、重命名和删除节点。
- [ ] 点击“新建节点”后，空白处单击能明确创建一个可见节点；失败必须显示可理解的错误和恢复操作。
- [ ] 画布存在遮罩、只读、离线或未连接状态时，界面必须明确说明哪些能力受限，不能保留可点击但无效果的工具。
- [ ] 使用新安装包在隔离项目和真实用户流程中各复测一次，保留修复后截图。

### 当前结论

已完成只读 P0 排查，**尚未修复**。根因不是用户操作、项目目录或安装包版本不一致：

- `app.html` 启动代码引用了不存在的 `#drawer-open-kit` 元素，并直接为它设置 `onclick`。
- 页面加载到该行时抛出 `Cannot set properties of null (setting 'onclick')`，后续初始化整体中断。
- 因此新建节点所依赖的画布 pointer/click 事件、首次渲染、视口初始化、本地桥初始化都没有执行；静态标题和工具栏仍会显示，造成“看似打开、实际完全不能操作”的假象。
- 已核对 `app.html`、`dist/app.v2.html`、`.deploy/app.html`、Windows 安装器 payload 的 hash 一致，说明当前安装包确实携带同一 P0 缺陷，不是本机装错版本。

### 最小修复方向

- [ ] 删除该失效按钮绑定，或改为元素存在时才绑定事件。
- [ ] 修复后必须验证：页面不再出现启动异常；画布 pointer 事件已注册；点击“新建节点”后在空白处可创建节点；`LiveDotApp` 与本地桥状态均已完成初始化。
- [ ] 重新构建 `app.html`、`.deploy` 与 Windows 安装器 payload，并用新安装包复测本记录全部 P0 验收项。
