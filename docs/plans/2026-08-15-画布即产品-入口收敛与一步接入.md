## 目标（用户视角，已确认）

- 用户认知里**画布就是产品本身**：双击快捷方式直接出画布，无任何中间窗口。

### 话题六：不改 AGENTS.md 能否每次稳定启用插件（技术验证，2026-08-15）

**用户原话**：

> 还有小问题如果不改用户的Agents.md你确定codex这种agent 能每次稳定地启用插件吗？你可以搜索一下我不确定 之前修改Agents.md是为了稳定 以增加不覆盖 指针的形式做的 不过我也不确定

**验证结论**（本机 `~/.codex` 实证 + 搜索佐证）：
- Codex 全局机制齐全：`~/.codex/AGENTS.md`（每次会话自动注入）、`~/.codex/skills/`（自动发现，按 description 按需触发）、`~/.codex/rules/`、`~/.codex/plugins/`、`~/.codex/memories/`、config.toml 的全局 hooks 与 `[projects.'...']` 项目级 hook（本机 config.toml 存在此前 livedot hook 测试残留，证明 hook 机制可用）。Claude Code 同理（全局 `~/.claude/skills`、全局 CLAUDE.md、全局 hooks）。
- 参考：[Codex skill 自动发现覆盖 .codex 路径](https://github.com/deftai/directive/issues/75)、[Codex 插件规范](https://cdn.jsdelivr.net/npm/@miniidealab/openlogos@0.9.30/spec/codex-plugin.md)、[claude-skills-library 的 Codex 运行时](https://github.com/frankxai/claude-skills-library/blob/main/runtimes/codex.md)。
- **三种机制与稳定度**：全局 Skill=按需触发（不强制）；全局 session-start Hook=每次会话机械执行（强制稳定）；全局 AGENTS.md 追加=每次注入规则文本（强制稳定但侵入全局指令文件最深）。
- **决策（采纳）**：接入 = **全局 Skill（知识底座）+ 全局 session-start Hook（每次自动读 map 汇报）**；两者均为"产品自行管理的追加条目/新增目录"，不碰项目文件、不覆盖用户全局内容、支持卸载清理。**纯 Skill 仅当用户接受"按需启用"时才够**；"每次自动读地图汇报"这一核心协作模式必须由 Hook 支撑（机制使然）。之前的"项目 AGENTS.md 增加不覆盖指针"方案废弃（改为用户级 Hook/Skill，理由：不污染项目、可清理、稳定度相同）。

**用户原话（摘要）**：

> 我的核心是,它那个不仅仅是项目状态,就说它把那个agent它的所有的操作过程变成一个就是一个地图嘛,就是我的核心就是双方可交互,人可以在地图上标注,然后标注节点,选择节点,然后复制节点,直接就是某一块地址信息,直接给agent,agent马上知道当前这个项目里面是哪块出了问题。然后agent他提出方案,你在地图上也能够实时地去看见,它一个执行的路线和方案。就是其实很简单,就是让它更简单去交互,而不只是一个看板。

> 这是之前跟chatgpt的讨论 差不多也是这个意思 所以具体怎么交互根据使用场景定的

**定位（对齐结论，作为本轮验收标准）**：
- 活点地图不是"项目状态看板"，而是**面向探索型任务的人机共享工作空间**：把线性的 Agent 对话/尝试过程变成**可分叉、可比较、可回溯、可重新进入的探索地图**；人保留判断权，Agent 放大探索能力。
- 核心四个点：**分叉记忆**（多路线并存）、**局部寻址**（人把某块地图信息直接交给 Agent）、**失败保留**（失败是探索资产）、**重新进入**（任何人/Agent 从某位置继续，不从头读全文）。
- 交互原则：**按使用场景定，极简优先**（不引入看板/任务管理形态）。

**现有支撑盘点**：
- 分叉记忆：方案线三态（success/failed/pending）+ 路线体系 = 树状探索数据模型 ✅
- 失败保留：`failed` + `shelved` + 标注原因 ✅
- 重新进入：Agent 侧 `map_get_context`（当前位置/失败回溯/下一步）；人侧打开画布回上次视图（本计划 T1）✅
- Agent→人实时可见：桥 SSE 事件 → 画布外部修改自动同步加载 ✅
- **局部寻址：缺口**——人无法"选中对象 → 把地址给 Agent"。本轮补齐（见 T3 新增"复制引用给 Agent"）。

### T3c 局部寻址："复制引用给 Agent"（定位核心交互）

- 文件：`app.html`、`agent-kit/skills/live-dot-map/SKILL.md`
- 改动：节点/方案线/路线的右键菜单（及属性面板）新增 **"复制引用给 Agent"**：选中对象 → 生成一段可粘贴文本（对象名、类型、当前状态、id、Markdown 路径、一句话摘要）→ 写入剪贴板 → toast 提示。用户在 Agent 对话粘贴后，Agent 凭全局 skill 立即定位该对象（id/路径/状态均可在 map.json 中找到）。
- **引用格式规范写入 SKILL.md**（人→Agent 寻址协议）：Agent 收到引用文本时解析出 id/路径，读取对应对象与 Markdown 上下文（此前尝试、失败原因、人的标注）再回应——不要求 Agent 记忆"刚才"。
- 交互极简：选中 → 复制 → 粘贴，不引入新面板。
- 验证：人工复制粘贴到真实 Agent 对话，确认 Agent 精准回答该对象上下文；`tests/web` 断言剪贴板文本包含 id 与 md 路径。

### T3d Agent 写回新对象高亮（"它刚画了什么"）

- 文件：`app.html`
- 改动：外部修改（Agent 写回）自动加载时，对比新旧文档，**新增的 Agent 创建对象播放 pulse 高亮**（复用现有 `.pulse` 动画）；来源标记（Agent · xx）照常显示。
- 验证：`tests/e2e/bridge-browser.mjs` 增补：外部写入新节点后画布加载且该节点带 pulse/高亮类。

### 话题八：通知原则——"无事不打扰，有事必回应"（2026-08-15，最终确定 Agent 通知机制）

**用户原话**：

> 所以说在这个使用场景下你到底要改哪些 推荐的是什么 本身就是改启用的时候启用但是不能漏掉人的任何一条地图新标注 新注释 改动 必须要通过某种方式让agent知道 hooks可以做到吗 我也不需要每次一个任务就汇报一下 那很影响开发 就是像浙江政府一样 默默记录 平时无事不打扰 有事必回应 这是原则问题 技术上怎么实现？

**原则（定为产品原则）**：Agent 通知 = **增量变更通知**，不是全量状态汇报。平时零打扰；人的任何一条新标注/注释/改动**一个不漏**地让 Agent 知道；不要求 Agent 每次会话主动汇报全局。

**技术方案（已定）**：
- **已读水位**：`.live-dot-map/agent-read.json` 记录"Agent 上次读到的时间"（Agent 侧标记文件，不污染 map.json 数据与 revision）。
- **变更检测**：session-start hook 读 map.json，找出所有 `updatedAt > 水位` 的对象（nodes/edges/anns/routes）与新标注（`attention:'new'` 优先列出），汇总为简短清单；随后**推进水位**。
- **条件汇报**：有变更 → 输出清单（增量，非全量）；无变更 → 完全静默（hook 零输出）。
- **人主动通道**：T3c"复制引用给 Agent"（指哪看哪，不依赖 hook）。
- **增强项（第二阶段）**：user-prompt hook——用户发消息时若水位之后又有新变更，注入一句"地图有新改动"提醒（Claude Code UserPromptSubmit / Codex 均支持注入上下文）。

### 话题九：六使用场景对照与实现确认（2026-08-15）

**用户原话（要点）**：核心是双方可交互——人标注/选节点/复制节点地址给 Agent，Agent 立即知道哪块出问题、实时写回执行路线与方案，而不是看板。六个场景：①探索没有标准答案的问题（多路线分叉/暂停/失败/比较，长期保留）；②人和 Agent 一起探索（同一张地图、双方操作）；③精确把"这一块问题"交给 Agent（复制节点引用，Agent 知道项目/路线/节点/md/历史/失败原因/标注）；④保留失败与未完成探索（绿/红/灰，失败不消失且保存原因）；⑤跨会话/跨 Agent/跨时间继续探索（状态外置为长期文件，可重新进入）；⑥多 Agent / Agent Team 共享状态层（分别执行、共享地图、人统一判断）。

**对照结论（逐场景）**：场景①④⑥当前数据模型与协议已支持（三态方案线/路线/shelved/来源标记/WAL 冲突保护/humanOnly）；场景⑤由 map_get_context（Agent 侧）与 T1 回上次视图（人侧）覆盖；场景②③是交互缺口，由 T3c（复制引用）与已有 SSE 实时同步覆盖，并新增 T3d（Agent 写回新对象高亮）。**全部六个场景在本计划实施后可达**。

## 方案决策记录

- **目标形态**：画布=产品本体，无启动器弹窗（用户提出并确认）。
- **Agent 一步边界（2026-08-15 重大修正）**：~~产品自动写项目配置 + 用户在 Agent 客户端一次信任~~ → **改为：插件装用户 Agent 全局（一次）+ 项目只放数据 + 用户一行提示词命令接入**；不存在项目级信任确认（原方案作废，理由见话题五）。
- **打开默认行为**：记住上次工作区（用户确认）。
- **面板形态（重要决策，2026-08-15）**：**绝不做常驻侧栏/面板**（ComfyUI 是生成图片工具，活点地图是思考工具，极简是核心）。文件类操作维持汉堡弹层，但支持**多层展开**（子菜单/分组展开）；视觉打磨向 **Apple / Linear 风格**（克制、层次、细腻）。
- **产品定位（话题七）**：探索型任务的人机共享工作空间；分叉记忆/局部寻址/失败保留/重新进入为验收标准；"复制引用给 Agent"（T3c）为本轮补的核心交互。
- **导出图片**：**直接移除该菜单项**（用户明确"一点用没有"），不做占位符也不补齐。
- **技术路径（内部决定，不拷问用户）**：
  - 桥会话内 open 任意本机目录（allowlist 扩展），而不是浏览器直读降级。
  - 文件夹选择用桥 spawn `powershell -STA` 的原生 `FolderBrowserDialog`（画布点击即弹系统选择器，体验与原生一致）。
  - 启动器 `--open` 无窗口化，桥 detached 后台运行。
- **被否方案**：a) 画布用 `showDirectoryPicker` 把所选目录交给桥（浏览器不暴露完整路径，不可行）；b) 画布内自绘目录树浏览器（工作量大、体验差于原生选择器）；c) 保留启动器仅作项目选择器（违背"无弹窗"诉求）；d) 常驻侧栏面板（用户明确否决）；e) 补齐"导出图片"（用户明确不要，改为移除）。

## 关键假设

- 假设桥 spawn PowerShell 弹原生选择器在目标环境（Windows 10/11 + PowerShell 5.1）稳定可用；若受限，回退为"最近工作区列表 + 手动输入路径"（体验降级但功能完整）。
- 假设放开桥的目录 allowlist 不引入新安全面（桥仅 loopback 暴露、会话+CSRF 保护、Agent MCP 通道不含此接口）。
- 假设"上次工作区"以产品目录文件记录足够（不做多用户/多设备同步）。
