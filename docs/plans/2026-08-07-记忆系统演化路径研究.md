## 〇、第一性原理:记忆系统的四个过程

一切记忆系统(人脑/机器)都回答四个问题:

1. **编码**:经历怎么被压缩成可存的形式?(人脑:皮层分布式表征;你的:节点/方案/一句话+md 分片)
2. **索引**:怎么按关联而非时间组织?(人脑:海马体互相关联的索引——Teyler & DiScenna 1986 海马体索引理论;你的:路线/分支图)
3. **检索**:用的时候怎么重构出来?(人脑:模式补全,回忆=重构而非回放;你的:Agent 读图+按需翻 md)
4. **生命周期**:什么被巩固、什么被遗忘?(人脑:睡眠重演巩固、突触衰减、杏仁核打重要性标签;你的:**目前缺失**——这是真问题所在)

关键洞察:**你的前三个过程已经有理论正确的结构,缺的是第四个**。用户的直觉「人的记忆本质也是索引」是对的——海马体索引理论就是这么说的。但人脑索引是「活的」(会巩固、会遗忘、有重要性),map.json 目前是「死的」(只增不减,全部平权)。

论文/产品依据(已研读):
- **HippoRAG**(NeurIPS'24, [arXiv:2405.14831](https://arxiv.org/abs/2405.14831)):LLM=新皮层、KG=海马索引、Personalized PageRank=模式补全。证明「索引+关联激活」结构本身能多跳推理(创新的一种弱形式),提升约 20%。
- **Generative Agents**(Park et al. 2023):记忆流 + importance/recency/relevance 加权检索 + 周期性 reflection 抽象。这是「杏仁核重要性标签」和「巩固出抽象结论」的最早产品级验证。
- **Sleep-time Compute**(Letta/UC Berkeley, [arXiv:2504.13171](https://arxiv.org/abs/2504.13171)):空闲时离线巩固记忆,测试时算力降 5 倍、精度升 18%。产品化先例:Claude Code AutoDream(会话间修剪/合并/整合)、Google Always-On Memory(30 分钟 cron 巩固)。
- **MemoryBank**(AAAI'24):艾宾浩斯遗忘曲线进 AI 记忆——衰减是特性不是 bug。
- **Zep/Graphiti**([arXiv:2501.13956](https://arxiv.org/abs/2501.13956))、Mem0、A-MEM(Zettelkasten 卡片+自演化链接,NeurIPS'26):当记忆条目上千、跨会话查询为主时,工业界收敛到「抽取→合并→图/向量检索」的管道。
- **Voyager**(TMLR'24):走通的经验沉淀为技能库——基底节「习惯化」的对应物,即你 PRD 里的「路线固化」。

## 二、回答几个具体问题(不分路径,各路径通用)

**「AI 能理解整张地图并按需读文档吗?」**
能,但有规模档位。小图全读;中图(数百节点)必须读「投影」(主路线链+pending+停滞+各路线一行摘要);千级以上纯读文件不够,需要检索层。投影不是妥协,是前额叶工作记忆的正确类比——人脑工作记忆也只有 4±1 槽位。

**「打分 60/70/80 怎么做?」**
三态(成功/失败/待验证)是粗分类,加 `score`(0–100)做细粒度,这就是杏仁核的重要性标签。三态负责视觉快速过滤(绿/红/灰),score 负责排序和 Agent 决策依据。不冲突,都要。

**「会有创新能力吗?」**
专家创新 vs RAG 不能创新,差别在于专家知识是**重组过的结构**(图式),RAG 是孤立片段。你的地图恰好是重组结构——这是它比向量知识库强的根本点。创新在产品里的形态 = Agent 在图上找**结构空隙**:停滞路线、低分区、两条路线的潜在交叉、高分方案的迁移场景。这个能力来自「读全局+找空隙」的协议循环,不来自底层格式。HippoRAG 的 PPR 是算法版关联激活;你的 Agent 遍历地图就是关联激活。

**「什么进地图,什么不进?」**
进:状态、打分、等待判断(pending)、决策与一句话原因、关联、停滞信号、md 指针。
不进:过程细节/原始日志(→md 分片)、时间流水(→git)、可从状态推导的信息(不冗余)。

## 三、三条分叉路径(结果层面不同,请你选)

### 路径 A:单图深化——地图即记忆,补全生命周期

**形态**:保持 map.json 唯一事实源 + 零依赖画布。补四样:score 打分、归档(衰减)、投影读取(前额叶)、整理例程(睡眠巩固=定期让 Agent 合并冗余/归档停滞/绿线沉淀 skill/重算摘要)。
**最终样子**:你打开画布,看到的就是全部记忆;Agent 每次会话读投影干活,定期「睡一觉」整理地图。人和 Agent 住在同一张图里,图永远可被人眼审阅。
**结果规模上限**:舒适区到数百节点;千级靠投影+归档硬撑,再大检索质量下降。
**代价**:最小——文档+协议+画布小改,无新依赖。
**推荐理由**:**推荐**。你的差异化就是「人也能住进去的共享记忆」;当前 20 节点到数百节点之间全是这条路的主场;所有被推迟的能力(检索/协作)都不堵死。

### 路径 B:双层记忆——地图(意识层) + 机器记忆库(潜意识层)

**形态**:地图保持人的界面不变;Agent 另有一个机器原生记忆库(embedding/时序知识图谱,Zep/Mem0/HippoRAG 类),所有经历自动进库,Agent 检索靠它;地图变成 Agent 从库中「提炼出来给人看」的策展层。
**最终样子**:规模上千节点也不怕,Agent 回忆能力强;但存在一个你看不见的 Agent 私有记忆层。
**代价**:引入向量库/KG 依赖(破零依赖红线);两个事实源需要同步机制;「人不知道 AI 记住了什么」——**恰好放弃你相对 Karpathy 框架的核心差异点**。
**推荐理由**:作为规模爆炸后的逃生舱保留,现在不做。触发条件明确:单项目节点稳定破千、投影规则实测漏关键信息。

### 路径 C:事件溯源——日志为底层,地图是投影

**形态**:底层改为 append-only 事件流(每次状态变更一条记录,JSONL),map.json 变成从事件流推导出的「当前投影」;时间旅行、回放、「上周我为什么放弃那条路线」都变成原生能力;git 的角色被内置到数据层。
**最终样子**:记忆的「时间维度」最完整,最接近人脑「经历流」;巩固例程=重写投影。
**代价**:数据层重写;Agent 要学会写事件而非改状态(心智负担上升);画布要处理投影与事件两级;对当前单人+单 Agent 场景,git 已提供 80% 的时间维度——增量收益不成比例。
**推荐理由**:概念上最「正确」,工程上此刻最不划算。git + map.json 已覆盖时间痕迹;除非未来要做「回放整个探索过程」类功能,否则不启动。

## 五、三条路径的优缺点与天花板(用户要求的直接对比)

| | A:单图深化 | B:双层记忆 | C:事件溯源 |
|---|---|---|---|
| **本质** | 地图=唯一事实源,补生命周期 | 地图=意识层,机器库=潜意识层 | 事件流=底层,地图=投影 |
| **优点** | 单一事实源永不分叉;人完全可审阅;零依赖;改动最小;今天就能验证 | Agent 回忆能力最强:语义检索能找到「嘴上说不出关键词的那条经验」;规模上万条;embedding 天然发现隐藏关联 | 时间维度最完整:回放、归因、「我上周为什么放弃这条线」原生可查;地图损坏可从事件流重放修复 |
| **缺点** | 千节点后投影质量依赖地图结构的整洁度;无自动关联,跨路线隐藏联系靠人/Agent 自己撞见 | 双事实源要同步;人看不见机器层——信任与审阅权丧失;引依赖破红线;非程序员复杂度上升 | 数据层重写;Agent 要学着「写事件」而非「改状态」,心智负担上升;事件流膨胀需要快照机制;单人场景 git 已给 80% 时间痕迹 |
| **规模天花板** | 数百节点舒适;千级靠归档+投影纪律硬撑;回忆精度随规模缓降 | 最高,工业级记忆系统都在这层(万条级) | 与 A 相同(投影仍受读取预算限制) |
| **时间维度天花板** | 靠 git:能查历史但查询不便 | 取决于机器库(Zep 时序 KG 很强) | 最高,原生 |
| **创新能力来源** | 协议循环:遍历地图找结构空隙 | 语义相似性自动关联(理论上最强,但关联结果人不可见) | 同 A,外加「跨时间模式」可分析 |
| **与你目标的贴合** | 「人机共享记忆」完整保留 | **恰好放弃**核心差异点(出现人看不见的 Agent 私有层) | 保留共享性,但工程成本前置 |

### 最终判断:A 最符合你的第一性原理

按你的目标逐条过:人机共享可审阅(A✓ B✗ C✓)、本地优先零依赖(A✓ B✗ C✓)、长程持续更新+全局思考(A✓ B✓ C✓)、创新机制(A/C 靠协议循环,B 靠黑盒检索)、非程序员可用(A✓ B△ C✓)。

**更准确的图景:A 不是和 B/C 平行的单选,而是主干。** B 和 C 是 A 的两个升级方向:
- A 做完生命周期后,规模撞墙 → 从 A 上长出 B(只加检索层,不动契约);
- 需要「回放/归因」类功能 → 从 A 下沉到 C(map.json 变投影)。
选 A 不锁死任何东西;选 B/C 则今天就要付出全部复杂度,去换一个你还没撞到的天花板。

**A 的真实天花板要说透**:它不是「地图装不下」,而是「投影质量依赖地图整洁」——如果 Agent 和你长期不整理,路线结构乱了,投影就读不出全局。这正是「整理例程」(睡眠巩固)存在的理由:它不是锦上添花,是 A 路线的承重墙。
