## 本轮要达到的结果

一个非程序员用户可以先安装活点地图、再在真实项目中用一次明确动作接入正在使用的 Agent；画布只在真实协作就绪时显示“已连接”。用户能给地图命名、把节点标为问题、在地图内书写并保存节点 Markdown。所有这些改动都经本地桥可靠落盘，刷新、重启和旧地图迁移不会丢失或伪造状态。

## 本次产品决策

| 决策 | 采用的结果 | 不采用的旧做法 |
|---|---|---|
| 安装与项目 | 先安装软件，可见且可更改安装位置；项目只在产品内首次接入时选择 | 安装器首页就要求项目文件夹 |
| Agent 接入 | 一个“接入当前 Agent”动作，只显示真正检测到且可继续的下一步 | 罗列四个平台、协议文件和技术状态 |
| 协作状态 | 本地桥、项目和 Agent 三项均就绪才显示“已连接”；其余显示准确可恢复状态 | 桥在运行、页面却写“降级”或“已连接” |
| Markdown | 画布内提供极简文本详情的打开、编辑、保存；可选“在文件夹中显示” | 只显示相对路径或只读空白弹窗 |
| 问题表达 | “问题节点”是独立节点语义，红色可一眼辨认；“从问题建立路线”是另一个可选动作 | 用“升级为问题路线”代替问题节点 |

### 已知规范变更

现有 UI 规范把红色只定义为失败方案线。本轮依照真实用户要求，为**问题节点**新增独立红色语义；方案线的红色失败状态不变。实现前必须同步 PRD、UI 规范和品牌语义，确保节点与方案线在视觉上仍能区分，不把“问题”误读成“该方案已失败”。

## 逐项实施与验收

### 1. 冻结复现样本与回归基线

**现有**：`E:\壁纸制作` 已在真实测试中产生 v2 地图、空 `n2.md` 和本地桥状态；问题可复现，但尚未形成可自动回归的样本。

**改成**：建立不含用户内容的匿名测试项目夹具，覆盖旧安装、刷新、空 Markdown、问题节点和真实 Agent 接入状态。保留原项目文件，不把测试脚本写入用户项目。

**涉及**：`test/`（新增夹具和端到端场景）、现有安装器/本地桥测试脚本。

**验收清单**：

- [ ] 用全新临时项目复现 01–05 的旧问题，并记录旧行为为反向回归用例。
- [ ] 测试不读取、不修改 `E:\壁纸制作` 的真实内容。
- [ ] 旧版安装目录、v2 地图、空 Markdown、已存在 Markdown 各有独立夹具。

### 2. 固化协议：地图名称、问题节点与 Markdown 内容

**现有**：地图名称退化为项目文件夹名；节点只靠自由文本 `type` 和“问题路线”表达问题；Markdown 路径存在但没有可靠读写契约。

**改成**：

- 顶层 `map.name` 是可编辑地图名；项目目录名仅作为来源/连接信息，不覆盖地图名。
- 节点增加受校验的稳定语义 `kind: "goal" | "problem" | "result"`；旧 `type: "问题"` 自动识别为 `kind: "problem"`，未知旧字段原样保留。
- 问题节点可独立存在；只有用户或 Agent 明确选择时，才从该问题创建问题路线。既有问题路线仍可读写。
- Markdown 路径继续保持稳定；内容读写只能通过本地桥的受限接口，采用原子写入、大小限制、路径穿越与符号链接逃逸防护。

**涉及**：`docs/map-json-v2.md`、`docs/agent-protocol.md`、`src/shared/index.ts`、对应测试与构建产物。

**验收清单**：

- [ ] 新地图可保存独立名称；改名不移动任何 Markdown。
- [ ] 新建、转换、Agent 写入的问题节点都带 `kind: "problem"`，并保留创建者、更新时间和 revision。
- [ ] 旧 `type: "问题"`、既有问题路线、未知字段和已有 Markdown 在迁移后都不丢失。
- [ ] schema 校验拒绝非法 `kind`、非法 Markdown 路径、项目根目录外路径和符号链接逃逸。
- [ ] 协议文档、MCP/Agent 说明与命令校验同步，不允许 Agent 伪造问题来源或绕过命令处理器。

### 3. 先修本地桥会话与真实协作状态

**现有**：首次启动后地址栏移除一次性令牌；刷新页面时画布无法恢复会话而错误进入降级模式，即便本地桥仍正常运行。设置页还把“项目已选”“桥在运行”“Agent 已接入”混为一件事。

**改成**：本地桥在同一浏览器会话内可安全恢复连接；UI 由桥会话、项目授权、当前 Agent 自检三项共同计算唯一状态。刷新、重开画布、桥重启都必须显示事实，而不是猜测。

**涉及**：`src/web/bridge-client.ts`、`src/bridge/`、`src/web/runtime.mjs`、`app.html` 生成流程、桥/API 测试。

**验收清单**：

- [ ] 首次桥启动、浏览器刷新、关闭后重新打开、桥重启四种情况下，状态均能在 10 秒内收敛。
- [ ] 桥可用但 Agent 尚未接入时，不显示“已连接”。
- [ ] 只有桥、项目与当前 Agent 都通过自检时，才显示“已连接”。
- [ ] 断桥、会话过期、项目不可访问、Agent 未信任时，分别给出用户能理解的一步恢复动作；不出现底层 token/JSON/MCP 术语。
- [ ] 自动化测试证明不再依赖地址栏的一次性令牌维持会话；安全测试仍验证跨来源不能复用会话。

### 4. 给本地桥补齐 Markdown 可靠读写能力

**现有**：桥能打开项目和读写地图，却没有 Markdown API；`app.html` 只尝试浏览器文件夹授权。桥模式下点击 Markdown 必然失败；即使读到文件，也只有只读预览。

**改成**：桥新增受会话保护的 Markdown 读取、首次创建、保存和在文件夹中定位能力。创建与保存走安全的原子写入；失败保留可见错误及重试，绝不产生“已打开/已保存”的假成功。

**涉及**：`src/bridge/server.mjs`、`src/bridge/project-store.mjs`（或专门 Markdown 存储层）、`src/web/bridge-client.ts`、桥安全/故障注入测试。

**验收清单**：

- [ ] 强协作模式下，打开节点 Markdown 不依赖浏览器文件夹授权。
- [ ] 不存在的详情会创建含节点标题的初始文本，随后直接进入编辑态；不会留下无提示的 0 字节文件。
- [ ] 保存后刷新画布、重启桥、由 Agent 读取，均得到同一份内容。
- [ ] 磁盘满、权限撤销、桥中断、并发修改时，页面不显示成功，并提供保留草稿/重试/冲突处理。
- [ ] 尝试读取 `..`、绝对路径、项目外路径、符号链接目标和超大文件均被拒绝且不泄露项目外内容。

### 5. 重做安装器：只负责安装软件和自我修复

**现有**：安装首屏要求项目文件夹；不显示或不能修改软件安装位置；旧版本不兼容被称为“损坏”，并要求用户手动删除 `current`。

**改成**：安装器只完成软件安装。首屏明确显示默认安装位置和“更改位置”；安装完成后打开产品。发现旧版或不完整安装时，安装器自动安全替换/修复，用户不会接触 `current` 内部目录。

**涉及**：`installer/winforms/Program.cs`、`installer/README.md`、`scripts/build-windows-installer.mjs`、`scripts/verify-windows-installer*.ps1`。

**验收清单**：

- [ ] 首次用户可查看默认安装位置并选择另一个用户有写权限的位置；安装器不要求管理员权限。
- [ ] 安装阶段不出现“项目文件夹”“Agent 协议”或项目内容写入动作。
- [ ] 旧版、缺文件、安装中断三种情况均由“安装/更新”自动恢复；不要求删除 `current`。
- [ ] 发生替换前保留可恢复备份；失败时旧可用版本不被破坏。
- [ ] 安装完成后启动正式画布；卸载仍保留用户地图并明示保留范围。
- [ ] 桌面快捷方式、开始菜单入口和应用窗口标题统一显示“活点地图”；本地桥不作为用户可见产品名称或独立入口。
- [ ] 双击“活点地图”后由产品按需启动本地桥；用户不需要启动、配置或理解本地桥。
- [ ] 桌面图标使用正式产品图标，而不是齿轮/服务程序样式。
- [ ] Windows 自动化 UI 测试覆盖默认路径、改路径、旧版升级、失败恢复与卸载保图。

### 6. 把“接入当前 Agent”收敛为一次产品动作

**现有**：项目在安装时已选，画布里又要求选择文件夹和粘贴协议；同时展示 Codex、Claude、Kimi、CodeBuddy 四个“待信任”状态，普通用户不知道下一步。

**改成**：首次在画布选择项目后，只保留一个“接入当前 Agent”入口。产品检测当前环境，直接执行能自动完成的配置；必须由 Agent 确认的步骤则给出一条可复制的自然语言请求。完成后只显示当前 Agent 的真实名称与协作状态，其余平台进入帮助层。

**涉及**：`app.html`、`src/web/`、`agent-kit/`、各 Agent 适配与 doctor/self-test、相关 UI 测试。

**验收清单**：

- [ ] 新用户安装后首次打开画布，未被要求再次选择项目或阅读协议文件。
- [ ] 选择项目并点一次接入后，用户只看到当前可用 Agent 的下一步；未安装的平台不干扰主流程。
- [ ] Codex、Kimi、CodeBuddy/WorkBuddy 各在真实客户端完成一次“接入 → SessionStart 注入 → 读取确认 → 写回”的闭环，未验收的平台不得显示已连接。
- [ ] 连接成功后，画布、桥、Agent 三端的项目根目录与 mapId 一致。
- [ ] 连接失败不写入半配置；“重新检测”可以幂等重复执行。

### 7. 统一画布交互：地图名称、问题节点与 Markdown 详情

**现有**：标题不可改；右键“升级为问题路线”含义不直观；Markdown 只显示路径/空预览。设置抽屉暴露大量实现细节，抢占画布注意力。

**改成**：

- 左上角地图标题可直接点按重命名，项目目录名保持为辅助信息。
- 新建节点菜单及节点右键提供“设为问题节点”；问题节点有独立、可辨识的红色外观和无障碍文本，不改变方案线状态。
- “从问题建立路线”是问题节点的次级操作，明确表达会建立一条后续探索路线。
- “打开 Markdown”打开极简可编辑详情面板：标题、正文、保存状态、关闭；不做富文本/聊天/文档库。
- 设置主层只保留必要状态与一个恢复动作，底层协议和多平台列表移入帮助层。

**涉及**：`app.html`、`src/web/runtime.mjs`、`src/web/bridge-client.ts`、`brand-spec.md`、`UI设计需求文档.md`、`产品需求文档-PRD.md`。

**验收清单**：

- [ ] 用户可在两步以内为地图重命名；刷新、Agent 读取、重新打开后名称不变。
- [ ] 新建问题节点与普通节点在画布、属性面板、`map.json` 和 Agent 检索结果中都可明确区分。
- [ ] 问题节点的红色与失败方案红色在线型、形状、标签和辅助文字上可区分；色觉辅助检查通过。
- [ ] 打开/编辑/保存/关闭 Markdown 不需要文件管理器、浏览器权限弹窗或技术知识。
- [ ] 画布空闲时不常驻显示协议、文件路径、四个 Agent 列表或多段说明文字。
- [ ] Chrome、Edge、Firefox、Safari 的强模式与降级模式各自显示一致且真实的能力边界。

### 8. 把问题节点接入 Agent 检索与协作规则

**现有**：检索把 `type` 当普通文本词元，没有“未解决问题”优先级；Agent 不能稳定知道应围绕哪些问题继续探索。

**改成**：问题节点进入确定性检索、全局推进摘要和 Agent 会话提示。默认优先召回当前路线/当前节点相关的未解决问题；Agent 创建或更新问题节点时，必须写入简短问题说明与证据 Markdown，避免只堆红点。

**涉及**：`src/shared/index.ts`、`src/cli/livedot.ts`、`agent-kit/`、`docs/agent-protocol.md`、检索和真实 Hook/MCP 测试。

**验收清单**：

- [ ] 新建的人类问题节点在相关查询中排在普通节点之前，且返回“为何召回”。
- [ ] 不相关路线的问题不会压过当前路线的一跳邻域；归档/已解决问题遵守现有历史召回规则。
- [ ] Agent 的 SessionStart/本轮检索能引用当前未解决问题 ID；写回时能更新其 Markdown 证据。
- [ ] 测试验证问题节点不强迫 Agent 自动创建新路线；重大方向仍按现有自治门禁要求人选择。
