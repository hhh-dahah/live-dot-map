# 阶段 2 计划：在 Excalidraw fork 上复刻 canvas.html 画布功能

> 日期：2026-08-06。需求基线：`canvas.html`（验收样板）+ `设计细节.md`（走查结论优先于 PRD）。
> 工程目录：`D:/桌面/活点地图/excalidraw`（下称 `<ex>`），`yarn start` 本机 3001 端口，改 packages 源码热更新生效。

## 需求复述

- 用 Excalidraw 画布引擎实现 `canvas.html` 展示的全部画布功能与操作逻辑。
- 数据写死固定示例；不做文件读写、不接 Agent、不做导入导出（阶段 3 的事）。
- 验收：对照 `canvas.html` 逐功能走查，**交互一致**；视觉接受 Excalidraw 组件的天然差异，不要求像素级。

## 方案决策记录

- **选择：方案 A（组合原生元素）**——节点=ellipse+bound text，方案线=arrow+binding，便签=rectangle+bound text；定制集中在 UI 裁剪、交互逻辑、主题令牌。
- **理由**：最大化继承 Excalidraw 引擎/导入导出/美观度（用户用它的初衷）；跟随上游更新冲突面最小。
- **被否选项**：方案 B（自造元素类型）——元素类型是封闭 union（`<ex>/packages/element/src/types.ts:206`），渲染/碰撞/序列化全是硬编码 switch，工程量大数倍且持续影响导入导出。
- **执行策略**：A 为主，个别交互原生机制做不像时，仅对该点深度定制（方案 C 作为 A 的兜底，不独立实施）。
- **关键假设**（做错时回溯用）：
  1. ellipse 的 bound text 机制可改造出「正圆随文字自适应」（改 `<ex>/packages/element/src/textElement.ts` 的 `handleBindTextResize`，宽高取 max）。
  2. arrow 的 `startBinding/endBinding = null` 原生支持悬空端，绑定/吸附/elbow 弯折原生够用（`<ex>/packages/element/src/binding.ts`、`elbowArrow.ts`）。
  3. 箭头 label（arrow 作 text 容器）原生支持，可实现「方案名附着在线上」。
  4. 自定义字段走元素基座的 `customData`（types.ts:81，序列化/restore 透传），存 status/route/编号等。
  5. 自定义选中面板用 `<Sidebar>` 子组件机制（`<ex>/packages/excalidraw/components/Sidebar/Sidebar.tsx`），在 excalidraw-app 层实现，不动 package。
- **走查优先于 PRD**：PRD §5.2/§5.4（红灰线禁止连接、标成功自动建点）、§8.2（画布显示编号）已被走查 10/3/7 推翻，以走查为准；PRD 在本阶段顺带修订。
- **已确认的语义统一**：删除节点的级联统一为——节点被删时，指向它的线变灰悬空、从它出发的线随删（Delete 键与右键菜单一致）。
