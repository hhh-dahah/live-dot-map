# 阶段 3：协议层与 HTML 正式化路线（2026-08-06）

> 本计划由 explore-plan 流程产出，经用户确认后按阶段执行。
> 背景：阶段 2（Excalidraw fork 复刻）路线被用户推翻——底层要做自定义的记忆系统/数据格式，fork 约束大于收益。fork 已存档：GitHub 私有仓库 `hhh-dahah/live-dot-map-canvas`（master 干净基线）+ 本地 `wip-stage2` 分支（deepseek 工作 + Kimi W1–W14 修复），作为参考实现保留，不再投入。

## 需求复述

- 回到 HTML 原型路线：以定稿的 `canvas.html`（阶段 0 验收样板）为交互与视觉基准，演进为正式可用产品。
- 底层自研：数据存储格式、交互、人机读写习惯全部按「人机共享记忆」重新设计，不继承 Excalidraw 数据模型。
- 即时价值：用户的壁纸项目（`E:\壁纸制作`，三件套 md 记忆系统已线性爆炸）是第一个真实迁移对象，协议层要先跑起来解决他自己的记忆问题。
- 性能未知需实证：百级节点（PRD §11.5）下不能卡。

## 方案决策记录

| 决策点 | 选定 | 被否 | 理由与假设 |
|---|---|---|---|
| 画布路线 | 自研单文件 HTML（canvas.html 演进） | 继续修 Excalidraw fork | fork 的数据模型/交互约束与「共享海马体」底层冲突；组件美观收益不抵改造成本。假设：现有原型交互已是验收样板，演进比重写快。 |
| 推进顺序 | 协议层先行，画布并行产品化 | 先把产品做完再迁移 | 「文件即接口」：没有产品本体协议也能跑；壁纸项目立刻受益；迁移实测反过来验证数据格式设计。 |
| 文件读写形态 | 纯浏览器 File System Access API + 轮询自动同步；非 Chromium 降级为导入/导出 | 本地常驻服务器、Tauri/Electron 桌面壳 | 零安装零依赖红线；轮询 lastModified 即可实现「Agent 改完画布自动刷新」。假设：日常使用 Chromium 系浏览器。本地桥留 P1 可选增强。 |
| 数据格式 | 自定义 map.json v1（版本化；结构/状态/位置/链接入索引，长文本进 md 分片） | Excalidraw JSON、SQLite 等数据库 | 人机共读、git 友好、Agent 一次全读得起；这是「共享海马体」的核心资产。 |
| 产品分发 | 一个应用 HTML，打开任意项目文件夹并记住最近项目 | 每个项目目录复制一份 MAP.html | 避免 1700 行文件散落各项目；PRD §9.1 的目录结构保留（map.json + nodes/ + routes/ + AGENTS.md），MAP.html 变为可选。 |
| 产品本体文件 | 新文件 `app.html`（从 canvas.html 复制起步），canvas.html 保持冻结样板 | 直接改 canvas.html | 保留验收基线便于走查对照；不破坏「原型冻结」约定。 |

## 阶段 A：文档一致性 + 协议层 + 壁纸狗粮（1–2 天）

- A1 文档修正：`goal.md`（阶段 2 结论改为「fork 路线否决并存档」，阶段 3 改本计划）；`产品需求文档-PRD.md` §11.1（Excalidraw 基础→自研单文件 HTML）、§11.2 改写、§9.1 文件结构定稿 map.json、§16 现状更新；`implement.md` 补路线修正日志；`AGENTS.md` 当前阶段与目录结构同步。
  验证：四份文档互引一致，无「当前正在基于 Excalidraw」类残留表述。
- A2 设计 `docs/map-json-v1.md`：meta（version/name）、routes[]、nodes[]、edges[]（status 与 connection 解耦：status 字段独立；to 可空=悬空）、annotations[]；每对象含 id/名称/路线/位置/md 相对链接/createdAt/updatedAt（供停滞检测）；名称≤20 字、note≤80 字约束（保证索引一次全读得起）。
  验证：用 PRD §13 两个典型案例手工建模，能无损表达。
- A3 写 Agent 协议段（模板，放 `docs/agent-protocol.md`）：会话开始读 map.json 后必须主动输出地图摘要（主路线当前位置、pending 方案清单、停滞超 N 天路线）；干完活同步更新地图的规则；状态/连接解耦规则；节点/方案/md 分片命名规则；「已否决路线勿再提议」抑制规则。
  验证：协议段自包含，贴进任意项目 AGENTS.md 即可用。
- A4 壁纸项目迁移（狗粮）：读三件套 → 生成 `E:/壁纸制作/map.json` 草稿（主线+专题线+问题线+发布渠道线；pending 全部显式化；已排除平台标 failed+shelved 注明勿再提议；节点挂现有 md 链接不新建内容文件）→ 壁纸 AGENTS.md 挂协议段。
  验证：用户在壁纸项目开新会话，Agent 主动输出地图摘要并正确回答「接下来该干嘛」。
- A5 画布只读打通（提前验证渲染）：新建 `app.html`（复制 canvas.html 起步），支持从 map.json 加载渲染（文件选择器读入即可，不写回）。
  验证：壁纸 map.json 在画布上正确渲染，截图走查。

## 阶段 B：画布产品化——文件读写（2–3 天）

- B1 数据层解耦：`app.html` 内存状态 S ↔ map.json 双向映射（serialize/deserialize 独立成段）；无文件时才注入 demo 数据。
- B2 打开项目：showDirectoryPicker 授权项目文件夹，读 map.json + 校验版本；目录 handle 存 IndexedDB，二次打开自动恢复。
- B3 自动同步：2s 轮询 map.json 的 lastModified，外部（Agent）写入后自动重载 + 轻提示「地图已更新」。
- B4 性能压测：脚本生成 200 节点/400 线（及 2x）的 map.json，Playwright 实测平移/缩放/选择流畅度；不达标则优化（视口裁剪、渲染合并），仍不达标再换 Canvas 2D 渲染层（交互层不变）。
  验证：压测实测 60fps 或接近；壁纸项目日常规模（<100 节点）无压力。

## 阶段 C：编辑落盘（P0 收尾，3–4 天）

- C1 全部现有交互（建节点/拉方案线/三态/吸附脱钩/便签/路线升级/删除级联/面板编辑）写回 map.json：防抖 + 原子写（tmp 文件 + rename）。
- C2 md 分片：节点/方案关联 `nodes/`、`routes/` 文件的创建与打开（路径约定 + 面板入口）。
- C3 非 Chromium 降级：导出/导入 map.json（download/upload），功能不缺失仅同步方式降级。
- C4 全量走查（对照 `设计细节.md` 与 canvas.html 样板）+ 文档同步 + git 提交。
  验证：双向闭环实测——Agent 改文件→画布自动刷新；人改画布→Agent 新会话读到。

## 阶段 D（P1，另立计划）

本地桥（网页内发任务/实时推送/直开 md）、搜索与路线聚焦、Agent 更新高亮、迁移向导产品化（「已有 AGENTS.md 项目？一分钟变成活点地图」）、路线固化为 skill（PRD P2 先记录不做）。

## 风险

- FS Access API 仅 Chromium → C3 降级兜底，P1 本地桥补 Firefox/Safari。
- 人与 Agent 并发写冲突 → 原子写 + 变更提示；冲突合并留 P1。
- map.json 随项目膨胀 → 名称/note 长度约束 + 超阈值按路线分片（v2 再议）。
