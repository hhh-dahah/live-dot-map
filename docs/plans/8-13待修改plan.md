## 1. 方案决策记录

### 1.1 已选择

选择 2026-08-13 讨论中的 **方案 B：A 路线完整 V1**。

最终产品表现：Agent 在长程开放任务中会把大的探索方向、关键证据和结果保存到地图；失败后能从来源节点重新检索其他方向；新会话能从短摘要继续；地图变乱前先让人审核整理建议。

### 1.2 未选择

- 方案 A（交付保底版）：只补 Skill 和记录规则，不足以解决长期路线膨胀、失败回溯和新会话恢复问题。
- 选项 C（仿生直觉实验版）：保留为后续研究，不进入三天交付。它包括图扩散/PPR、多维重要性、惊讶度、跨路线类比和探索/利用算法，需要真实数据和对照评测。
- 旧研究路径 B（地图 + 隐藏机器记忆库）：当前不做，避免双事实源和人不可见记忆。
- 旧研究路径 C（事件溯源）：当前不做，不增加 `attempts[]` 或完整事件流；现有 WAL 只负责可靠恢复，不承担产品记忆语义。

### 1.3 关键假设

1. 节点、路线、三态方案线、评分和 Markdown 已足以表达人类尺度的探索记录，不需要新的事件模型。
2. 第一版单项目主要处于几十到数百节点，确定性图检索、BM25、短投影和整理纪律可以支撑。
3. Agent 不需要被活点地图接管；Skill 负责行为策略，MCP 负责能力，本地桥负责真实性和硬限制。
4. 用户要在原本的 Agent 对话框工作；画布只承担查看、人工修改、标注和审核整理建议。
5. 任何自动整理都不能静默改写人的记忆；取消审核后 revision 必须完全不变。
6. 本轮优先完成核心记忆体验，不同时重做 landing、公开商店分发或大规模视觉设计。

### 1.4 假设失败时的回退

- 如果几十到数百节点时短投影仍频繁漏掉关键内容，先加强跨路线结构检索，再评估选项 C。
- 如果真实 Agent 普遍不遵守 Skill，在有生命周期能力的平台增加更强 Hook 检查；没有生命周期能力的平台继续诚实标记“基础连接”。
- 如果整理预览无法控制节点增长，优先改进策展规则和阈值，不立即引入向量库。
- 如果用户认为路线当前位置字段增加了理解成本，画布默认不展示字段，只在摘要、选中路线和整理预览中使用。

## 5. 修改后的目标形态

```text
人修改画布 ─┐
             ├─ 本地桥 ─ map.json + Markdown（唯一事实源）
Agent MCP ───┘                 │
                               ├─ 全局推进投影
```

- **本地桥**：保证命令真实落盘、并发不静默覆盖、Agent 不越过硬限制。
- **画布**：默认保持简洁；只有用户主动整理或达到软阈值时出现轻量审核入口。

## 6. 数据与协议调整

### 6.1 不新增探索事件集合

本轮禁止增加 `attempts[]`。一次大尝试仍用现有对象表达：

```text
来源节点 -- pending 方案线 --> 结果节点
                         └── .live-dot-map/routes/<edge-id>.md
```

结束时只更新方案线状态：

- 成功：`status=success`，连接结果节点，Markdown 写证据和可复用结论。
- 失败：`status=failed`，连接失败结果节点或保留已有结果节点，Markdown 写失败原因和排除条件。
- 尚未完成：保持 `pending`，Markdown 必须写已知证据和明确下一步。

### 6.2 路线当前位置

为 `routes[]` 增加可选字段：

```json
{ "currentNodeId": "n12" }
```

规则：

- 值必须引用同路线的现存节点。
- 缺失时保持兼容，由投影函数根据图结构和最近更新推测，并明确标记“推测位置”。
- Agent 或人推进到新的大节点时可更新；普通文件修改不更新。
- 改显示名称不影响该引用。

不保存容易过期的路线摘要；摘要每次从图和 Markdown 重新计算。

### 6.3 大尝试 Markdown 模板

方案 Markdown 固定为简短栏目：

```markdown
# 方案名称

## 目标或假设
## 关键行动
## 证据
## 结论
## 失败原因
## 后续建议
```

规则：

- 只写影响路线判断的行动，不贴完整日志。
- 证据必须能指向项目文件、测试结果、外部资料或人的标注。
- 成功时“失败原因”可省略；失败时“结论”和“后续建议”不可省略。
- 节点标题和方案标题继续遵守简洁协议，超长内容进入 Markdown。

### 6.4 全局投影输出

`map_get_context` 在空查询或 SessionStart 场景增加 `projection`：

```text
总目标
主路线当前位置
当前活跃路线（最多 3 条）
待验证方案（最多 3 条）
最近成功/失败的大尝试
停滞路线
待处理人类标注和里程碑
```

要求：

- 默认 10–15 行，不吞入整张图。
- 每项引用稳定对象 ID。
- 明确区分存储的当前位置和推测位置。
- archived/shelved 默认不进入投影。
- 相同 revision 产生确定性顺序。

### 6.5 整理预览

新增只读 MCP 能力 `map_plan_consolidation`，不直接修改地图。返回：

- 触发原因：用户主动、活跃节点超过 20、路线停滞、重复密度过高。
- 整理前节点/路线/方案数量。
- 建议列表：合并节点、压缩路线摘要、归档失败方案、重连重复分支。
- 每条建议涉及的对象 ID、理由、证据路径和拟执行命令。
- 整理后的预计数量。

用户取消：不得写 WAL、不得增加 revision。

用户确认：先创建恢复检查点，再把用户勾选的建议作为一个命令 envelope 提交；Agent 只能提出整理建议，不能自行把失败方案静默归档。
