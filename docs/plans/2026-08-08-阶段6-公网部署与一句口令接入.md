# 阶段 6：双点部署 + 多源兜底 + 数据目录规整

> 2026-08-08。目标场景：非程序员在自己项目目录对 Agent 说「接入活点地图」→ Agent 全自动完成：项目里建好 `.live-dot-map/` 数据目录、下载 app.html 到系统固定路径、桌面创建带图标快捷方式、注入协议到 AGENTS.md、初始化/迁移地图、拉起画布打开。网站同时提供手动下载入口。部署为双点：Cloudflare（海外/代理用户）+ CloudBase 静态托管（国内直连）。

## 方案决策记录（含讨论中确认的假设，供回溯）

- **双点部署**：Cloudflare Workers Static Assets（现有，`https://app.live-dot-map.workers.dev`）+ 腾讯云开发 CloudBase 静态托管（新增，默认域名 `tcloudbaseapp.com`，国内免备案）。理由：用户画像为「国内 + 常年开代理的程序员」，单点怎么选都有人别扭；Cloudflare 域名在大陆访问不稳定（用户本机 curl 已被 Clash 拦实证）。文件两点完全一致。
- **多源兜底**（替代单 curl 命令，用户揪出的假设错误）：setup.md 下载步按序尝试 ①curl Cloudflare ②curl CloudBase 镜像 ③Windows PowerShell `Invoke-WebRequest` / Linux `wget` ④Agent 内置网页读取工具 ⑤全失败则明说，引导用户浏览器手动下载（landing「下载画布」按钮是终极兜底）⑥用户手里有 agent-kit 本地副本时完全不联网。口令本身也带双源。
- **程序与数据分离**（用户确认）：程序 `app.html` 固定 `~/.live-dot-map/` + 桌面带图标 .lnk 快捷方式（图标 favicon.ico；全程无管理员权限、不写注册表；卸载=删文件夹+快捷方式）；数据 = 项目内 `.live-dot-map/`（map.json + nodes/ + routes/），协议注入项目 AGENTS.md（含画布路径约定，解决「Agent 无记忆也要知道画布在哪」）。
- **数据目录从项目根改回 `.live-dot-map/` 子目录**（回归用户最初设计）：项目文件多时根目录 map.json + nodes/ + routes/ 三个条目太乱；改后根目录只多一个文件夹。画布仍连项目根（md 链接可达项目任意文档），app.html 优先读 `.live-dot-map/map.json`、兼容根目录旧文件。
- **不做传统安装向导/.exe**：单文件零依赖，向导每步皆伪需求；未签名 exe 触发 SmartScreen 蓝窗反而吓退非程序员。
- **网站双入口**：手动下载按钮（手动党）+ 一句口令（口令党）。
- **skill 包装：暂缓**。已论证可行（skill 文件夹可装整个产品含 app.html），但依赖公开仓库与生态目录差异处理，留到产品公开后；届时 skill 管「接入知识」，AGENTS.md 协议管「每次会话纪律」。
- **插件商店：暂缓**。各家无统一商店（Claude marketplace=GitHub 仓库、Codex 无商店、MCP 是服务形态与我们零服务设计相悖）；且商店是放大器，走查期不放大。触发条件：狗粮跑顺 + 决定公开仓库 → 再评估。
- **远期方向记 PRD**：E2E 加密 / 分享协作 / 网页内嵌 AI（注意内嵌 AI 与 E2E「服务器看不到明文」矛盾，届时 AI 只能跑浏览器端或用户自己的 Agent）。
- **自有域名：暂缓**（一年几十块 + 绑国内服务需 ICP 备案 1-3 周）。澄清：域名配套防护跟在 DNS/CDN 服务商（Cloudflare）而非注册商，以后买了绑上防护照旧。
- **唯一无法自动化的步骤**：画布连项目文件夹需用户亲手授权（FS Access 安全规定），流程末尾引导点一次。
- **更新策略**：Agent 每次接入总重新下载 app.html 覆盖（幂等、顺手拿最新版）；AGENTS.md 注入按标记判重。
- 密钥留在仓库外 `~/.live-dot-map/cloudflare.env`；不推 GitHub。

## 任务

### T1 数据目录约定改为 `.live-dot-map/`（schema/协议/画布同步）

- `docs/map-json-v1.md`：分片路径约定 → `.live-dot-map/nodes|routes/…`；写明地图文件位于项目根的 `.live-dot-map/map.json`。
- `docs/agent-protocol.md`：map.json 引用 → `.live-dot-map/map.json`；新增「画布位置约定」（程序在 `~/.live-dot-map/app.html`，用户说「打开画布」时拉起）。
- `agent-kit/AGENTS.snippet.md`：按协议重新生成。
- `app.html`：连接文件夹时查找顺序 `.live-dot-map/map.json` → 根 `map.json`（兼容旧项目）；新建时 `getDirectoryHandle('.live-dot-map', {create:true})` 后在其内创建；保存写回原找到路径；新建 md 分片路径用 `.live-dot-map/nodes|routes/…`。
- 壁纸狗粮迁移：`E:/壁纸制作/map.json`（及已有 nodes/routes 目录）→ `E:/壁纸制作/.live-dot-map/`；其 AGENTS.md 协议段换新。

### T2 app.html 加拖拽导入（ComfyUI 式）

- 画布容器 `dragover`（preventDefault + 边缘高亮）+ `drop`：取 `dataTransfer.files[0]`，限 `.json`，走 `importMap()` 同等逻辑（版本校验/确认覆盖/失败不动原图）。
- 验证：拖入壁纸 map.json 渲染；拖坏 json 提示且不破坏当前图。

### T3 新建 `agent-kit/setup.md`（Agent 执行版接入指引，多源兜底）

分步指令，命令可直接复制，每步注明「失败即停下报告」：

0. 判断 OS（Windows 为主，macOS/Linux 附差异）。
1. 装画布到 `~/.live-dot-map/`（app.html + favicon.ico）：**按多源兜底顺序**（CF→CloudBase→iwr/wget→Agent 内置 fetch→报告失败引导手动）；已存在也覆盖 = 拿最新版。若项目里已有 agent-kit 本地副本，直接拷，跳过网络。
2. 桌面快捷方式（带图标）：Windows PowerShell COM 建 `.lnk`（桌面路径用 `[Environment]::GetFolderPath('Desktop')` 防 OneDrive 重定向；IconLocation 指 favicon.ico）；macOS/Linux 附简化说明。
3. 建数据目录：项目根无 `.live-dot-map/` 则创建。
4. 注入协议：`AGENTS.md` 无「活点地图」标记才追加 snippet（幂等；无则新建）。
5. 初始化地图：有记录文档 → 迁移四步生成 `.live-dot-map/map.json` 草稿（明示用户审核，判断权在人）；全新项目 → 模板落 `.live-dot-map/map.json` 并改 `name`。
6. 拉起画布：`start/open/xdg-open ~/.live-dot-map/app.html`。
7. 告诉用户：画布里点「打开项目文件夹」选本项目——唯一手动步（浏览器安全规定）。

### T9 CloudBase 部署（新）

- `auth status` 确认已登录；`auth set_env` 绑定环境（候选 `test-d0gims26n5c5ce096`，执行时按查询定；不合用则新建专用环境）。

## 风险与注意

- 桌面快捷方式与 `~/.live-dot-map/` 是用户明确要求的产物，直接建真的。
- CloudBase 环境名含 `test-` 前缀，如该环境另有他用，执行时先查清再决定是否新建专用环境。
- 部署顺序：T9 拿到 CloudBase 域名后才能回填 T3/T4 的镜像地址，再执行 T8/T9 的最终上传，避免二次部署。
- `~/.live-dot-map/`（程序）与 `项目/.live-dot-map/`（数据）同名不同义，文档一律写全路径。
