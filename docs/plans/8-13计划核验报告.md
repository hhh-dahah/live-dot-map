# 8-13 计划核验报告

> 核验日期：2026-08-13  
> 结论：**可以进入受控人工验收；不能宣称产品已全部验收完成，也不能公开发布。**

## 一、先说结论

`8-13待修改plan.md` 之前把所有项目勾成完成，这个结论在独立复核开始时是错误的。复核实际找到了会破坏核心体验的阻断问题：Agent 身份可伪造、Agent 可绕过人类审核归档记忆、Windows 安装包在全新项目缺少 Skill、安装测试复用旧目录、整理失败仍可能显示绿色成功。

这些阻断项现已修复，并由真实 Codex、三浏览器、全新隔离安装和完整聚合门禁重新验证。因此现在适合由项目所有者开始人工体验，重点判断“产品是否自然、简洁、符合真实工作习惯”。

仍不能勾选的是：**只给 Agent 一个高层目标时，它是否会自主控制记录粒度、识别真实失败、回到正确来源并继续探索。** 自动脚本给了明确步骤和对象 ID，只能证明整条技术链能工作，不能代替这一项真实产品判断。

## 二、复核时发现并修复的问题

| 问题 | 复核时 | 当前结果 |
|---|---|---|

## 五、你现在应该怎么人工验收

建议先测核心协作，不先测公开下载渠道：

1. 用当前内部 Windows Setup 选择一个全新测试项目，确认安装位置和项目位置都由你选择。
2. 打开画布，确认状态不是降级模式，并查看 Agent 连接状态。
3. 在画布写一条人类标注，然后只给 Codex 一个自然的高层开放任务，不告诉它节点 ID、不逐步教它怎么画图。
4. 观察它是否先引用你的标注，再只记录人能读懂的关键尝试，而不是命令/文件级碎片。
5. 让第一条方向真实失败，观察它是否保存证据、回到来源、提出不超过 3 个替代方向，并在重大跨路线选择前问你。
6. 关闭并重启 Agent，确认首个摘要能说明失败原因、当前位置和下一步。
7. 在 20+ 节点时打开“整理地图”：先取消，再只批准一部分，再用“恢复整理前”撤回。
8. 故意同时改同一字段，确认画布显示红色冲突，绝不能显示绿色成功。

如果以上核心流程符合你的实际操作习惯，才继续做 Kimi、Claude、CodeBuddy/WorkBuddy 和普通小白下载安装体验；公开部署、商店、签名和三源一致性仍按上线计划单独处理。

## 六、最终判定

- **可以进入：** 项目所有者的受控核心人工验收。
- **暂不进入：** 普通用户公开下载验收、多 Agent 全平台正式兼容验收、生产发布。
- **最重要的待验问题：** Agent 在没有逐步脚本提示时，能否自然执行“大尝试记录 → 真实失败 → 回溯 → 替代 → 新会话恢复”。
