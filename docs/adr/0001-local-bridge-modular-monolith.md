# ADR-0001：本地桥模块化单体

- 状态：已接受
- 日期：2026-08-11

## 背景

纯浏览器 File System Access 无法在四浏览器中可靠提供锁、WAL、备份、原子冲突处理和 Agent hook。产品要求已确认保存 RPO=0、离线、本地文件可检查、无需管理员权限，同时保留单文件画布交付。

## 决策

采用本地模块化单体：`app.html` 负责画布交互；单个 `livedot.mjs` 负责 HTTP、SSE、MCP、命令 reducer、文件事务、检索与适配器入口。共享 schema/reducer/检索以 TypeScript 维护并在构建时打包；运行时不安装 npm 依赖。

浏览器降级模式继续可用，但明确标记为未启用 Agent 自动读取与并发保护，不宣称正式协同。

## 取舍

- 相比纯 HTML：多一个本地进程，但获得跨浏览器一致文件语义、可测试恢复和强制 Agent 闭环。
- 相比云端服务：没有远程访问与多人实时协作，但不上传数据、离线可用、运维面更小。
- 相比数据库/微服务：JSON 仍可直接检查和版本控制，单人产品无需承担数据库迁移和分布式运维成本。

## 失败模型

进程崩溃由 WAL 恢复；写入失败保持 dirty/error；旧 revision 同字段修改显式冲突；未知 schema 只读；外部损坏文件隔离；hook 失败保持未确认并在下一会话重投。

## 安全边界

只监听随机 loopback 端口；一次性令牌换 HttpOnly、SameSite=Strict 会话；校验 Host/Origin/请求体；项目根显式注册；所有文件操作验证解析后路径和符号链接不逃逸；外部字符串只作为文本渲染。

## 后果

发布产物增加 `livedot.mjs`，一键接入负责 Node 运行时与三种 Agent 适配。生产发布前必须通过存储故障、安全、四浏览器和真实 Agent 闭环门禁。
