## 一、作品简介（约 480 字，对齐初赛字段）

**项目名称**：活点地图（多 Agent 协同的共享探索记忆层）

**问题与场景**：长程复杂任务的探索状态散落在聊天记录里——方案分叉后难以比较，失败原因随会话淡忘，更换 Agent 必须重新解释上下文。多 Agent 协作时，各 Agent 各自执行，结果缺乏统一验证，执行证据难以沉淀与审计。

**核心解决方案**：活点地图提供多 Agent 协同的共享状态层。以本地 `map.json` 索引与 Markdown 分片为单一事实源，用节点（目标/问题/结果）、方案线（成功/失败/待验证三态）、路线与里程碑表达探索结构。人通过画布操作，Agent 通过统一命令层（10 个固定 MCP 工具 + 官方 Skill）读写同一份记忆，执行结果实时回写画布。

**创新点与差异化**：① 局部上下文寻址——任何节点、方案、路线可一键复制引用交给 Agent，无需重述项目上下文；② 失败资产化——失败方案不删除、可归档，验证工具强制每次尝试留下证据、失败原因与评分；③ 判断权在人——删除操作仅限人类、里程碑需人工审核、WAL 全量审计，Agent 无法越权。

**开放/复用价值**：Agent 无关。已提供 Claude Code、Codex、Kimi Code、CodeBuddy 四套官方适配器，任何理解文件协议的 Agent 均可接入；同一套机制可迁移到研发协同、智能运维、客服闭环等任意复杂任务场景。

**当前进展**：v2 核心完成——本地桥 WAL/冲突/恢复、多地图、四套 Agent 适配器已落地，真实 Codex 长程任务闭环验收通过；正在推进多 Agent 协作与更多平台适配。

## 二、方案 PPT 内容大纲（官方模板 8 章）

### P0 · 一页纸速览

- 项目名称：活点地图
- 一句话：**让人和 Agent 在同一张地图上探索未知**——聊天适合推进一条路，地图适合管理很多条路
- 六要素快填：问题（Agent 协作状态散落、失败易丢）/ 方案（map.json + Markdown 单一事实源，画布 + 命令层双入口）/ 差异化（局部寻址、失败资产化、判断权在人）/ 复用（Agent 无关协议 + Skill）/ 进展（v2 核心完成，真实 Codex 闭环通过）

### 第 1 章 · 场景与价值（评分 25%）

1. **目标用户与核心痛点**：Agent 重度用户与小团队；三个真实痛点——对话线性（多路线无法比较）、失败丢失（为什么没选它无从查证）、换 Agent 断档（上下文重新解释）
2. **真实场景**：以壁纸项目探索为例（换模型/LoRA/提示词/工作流多路线并行，分叉、暂停、失败、重新比较），再泛化到软件研发闭环（缺陷聚合→根因定位→修复→测试→复盘）
3. **可量化的价值**：跨会话恢复时间（分钟级→秒级）、失败复用率（同一失败不再重复尝试）、多 Agent 协作的一致状态（同一份证据、同一份判断）
4. **行业可复制性**：研发协同、零人工运维、智能客服、风控理赔——闭环结构相同，只是输入输出不同
5. **创新点与差异化**：与现有方案对比（聊天记录/文档/白板 vs 活点地图：状态即文件、人机双写、证据强制）

### 第 2 章 · 方案总览

- **架构图**（一页）：三层——画布层（人，app.html 单文件）/ 状态层（本地桥：WAL 事务、revision、冲突、检索、审计）/ 接入层（Agent：10 个 MCP 工具 + 官方 Skill + 4 套适配器）
- 端到端主流程：任务输入 → 拆解 → 执行 → 验证 → 证据沉淀 → 人审核 → 经验复用
- 技术选型必要性：为什么不用云端/不用现成白板/不用纯聊天（本地优先、Agent 无关、可审计）

### 第 3 章 · 多 Agent 协同设计（评分 25%）

1. **4 职能 Agent 设计**（附录 A Identity 清单，8 字段）：
   - 主控 Agent：任务输入、拆解、路线分配（对应路线/问题路线语义）
   - 执行 Agent：方案尝试、工具调用（对应方案线）
   - 验证 Agent：结果核验、证据检查（对应三态 + `map_validate` 强制证据）
   - 策展 Agent：整理建议、经验沉淀（对应 `map_plan_consolidation`、里程碑）
2. **AgentTeams 映射表**（必选要求）：角色编排=路线与问题路线；任务拆解=从节点建立问题路线；上下文传递=节点引用 + Markdown + 人类标注送达（SessionStart 注入 + ack）；状态追踪=三态方案线 + 里程碑 + `currentNodeId` + revision
3. **闭环 8 环节逐条对照**：任务输入/拆解/上下文传递/工具调用/结果验证/执行证据沉淀（WAL+Markdown）/审批与回滚（delete 仅人、里程碑审核、checkpoint 恢复）/经验沉淀（整理建议、归档复用）

### 第 4 章 · Skill 工程体系（评分 25%，必选项）

1. **核心 Skill 清单**（附录 B 模板，9 字段）：`live-dot-map` 策展 Skill（读地图投影→判断推进位置→写回证据→维护 Markdown），附 `attempt.md` 尝试记录模板
2. **Skill 规格示例**：输入（投影/标注/查询）/ 输出（命令集）/ 调用条件（会话开始/用户提问/停止时）/ 失败处理（hook 失败不假装已读）/ 安全边界（只读白名单项目、不越权删除）
3. **与官方云 Skills 的关系**：阿里云官方用云 Skills 可作为执行能力补充（如云资源操作），活点地图 Skill 负责任务能力抽象层——两者职责分离
4. **复用价值**：同一 Skill 供 4 个 Agent 客户端共用；新平台只写适配器

### 第 5 章 · 工程落地、运行验证与安全可审计（评分 20%）

1. **可运行性**：交付 = `app.html`（画布）+ `livedot.mjs`（本地桥，零运行时依赖）+ agent-kit（适配器/Skill/模板）；双击即用（降级模式），正式协作走本地桥
2. **运行证据**：WAL 事件流（每次操作落盘 fsync）、revision 递增、20 个快照 + 7 天备份、损坏隔离 quarantine、冲突 409 双保留
3. **安全与审计**：loopback + CSRF + HttpOnly 会话；路径白名单（拒绝 `..`/符号链接/超限）；删除仅人可用；里程碑 `origin` 不可伪造（Agent 不得冒充 human_created）；高风险动作强制审批
4. **可观测与检索**：确定性投影（目标/主路线/当前节点/待验证/停滞路线/人类新标注）、图邻域 + BM25 检索、失败回溯候选；`map_validate` 强制证据闭环（缺证据不宣称成功）

### 第 6 章 · 开放/开源计划（评分 5%）

- MIT 协议；仓库结构（画布/桥/协议文档/agent-kit 全套）；文档齐全（PRD/map-json-v2/agent-protocol/UI 规范）
- 可复用成果：文件协议（map.json v2）、MCP 工具契约、Skill 模板、4 套适配器
- 后续：公开仓库、社区接入指南、更多 Agent 平台适配

### 第 7 章 · 落地计划与进展

- 当前进展：v2 核心完成（本地桥/多地图/4 适配器/真实 Codex 长程闭环验收通过）
- 里程碑：初赛（方案设计）→ 复赛（可运行 Demo：真实多 Agent 协作演示 + 评测证据 + 视频）→ 决赛（现场路演 + 端到端演示）
- 风险控制：多 Agent 并发冲突（已有 WAL/409 机制）、Agent 越权（命令层硬限制）、平台适配差异（适配器隔离）
