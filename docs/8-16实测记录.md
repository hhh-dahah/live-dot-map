### 0. 运行日志系统（前置基建，已完成）
- **现象**：产品无任何运行日志，桥和画布出错全靠用户截图口述，联动问题无法定位。
- **方案**（已确定并实施）：操作级 JSON 行日志，桥/画布/Agent 三端写同一个按天滚动的文件。
  - 新增 `src/bridge/logger.mjs`：`~/.live-dot-map/logs/livedot-YYYY-MM-DD.log`，保留 14 天，`LIVEDOT_LOG_DIR` 可覆盖（测试隔离）；日志写失败绝不阻断主流程。
  - 桥端（`src/bridge/server.mjs`）：记录启动/停止、每个 HTTP 请求（方法/路径/状态/耗时，**不记 URL 查询串**，bootstrap token 不落盘）、项目打开、命令提交（条数+revision）、MCP 工具调用、5xx 堆栈；4xx 只按 warn 记状态不记堆栈。
  - 桥新增 `POST /api/v1/logs/client`（认证 + CSRF，单次最多 50 条/256KB，非法级别降级为 info）。
  - 画布端（`src/web/bridge-client.ts`）：缓冲批量上报（1.5s 合批，error 立即发），埋点含初始化、项目切换、保存成功/冲突/失败、SSE 断连、Agent 同步、Markdown 保存失败；`window.error` / `unhandledrejection` 全局 JS 错误自动上报；降级模式只写 console。
  - Agent 端（`src/cli/livedot.ts`）：MCP/hook 进程启动与报错写同一日志（source=agent），进程级故障（`process.error`）也落盘。
- **改后效果**：每次操作后读 `~/.live-dot-map/logs/livedot-当天.log` 即可按时间线看到 人操作 → 桥处理 → Agent 写回 全链路；定位问题时把当天 log 贴出来即可。
- **验证**：新增 `tests/bridge/logger.test.mjs` 4 个用例；`node --test tests/bridge` 42 过、全量 `npm test` 100 过；真实 `livedot.mjs serve` 冒烟确认日志落盘。
- **状态**：已修复并已在真实安装中生效。已重建 `dist/windows-installer/LiveDotMapSetup.exe`（v2.0.0）并重装到 `E:\livedotmap\current`；实测 `~/.live-dot-map/logs/livedot-2026-08-16.log` 正常落盘，可见 `bridge.start`、HTTP 请求计时、`project.open` 与画布端 `client.init`（三端同文件时间线）。

### 1. 安装器「重装不生效」——已安装且文件完整时直接跳过重拷
- **现象**：用新构建的安装包在已有安装目录上重装，日志显示全部跳过，`payload/livedot-bridge-win-x64.exe` 仍是旧版（不含日志代码），新功能永远不生效。
- **根因**：`installer/winforms/Program.cs:564-567` `EnsureInstalledAsync()` 中 `if (HasKeyInstallerFiles(InstalledRoot)) return InstalledRoot;` ——只要旧安装「关键文件完整」就直接返回，完全不比对本次安装包的版本/文件哈希。「同版本不重拷」的优化实际变成「任何版本都不重拷」。
- **方案（已确定）**：
  1. `EnsureInstalledAsync()` 已安装分支改为：关键文件齐全 **且** 源 `payload-manifest.json` 与已安装的逐字节一致 → 跳过重拷（正确保留「同版本不重拷」优化）；否则走 `RepairInstalledAsync()` 备份-替换路径。比对 manifest 即可代表全部文件（manifest 内含版本号+每文件 SHA256），几 KB 瞬间完成，无需重哈希 160MB。
  2. `RepairInstalledAsync()` 状态文案按场景区分：更新场景提示「检测到新版本，正在备份并更新」，不再一律说「安装不完整」。
  3. 安装页 `LoadState()` 预告：安装包与当前安装不同时提示「将执行更新」。
- **改后效果**：出新包后运行一次安装包即完成覆盖更新（旧目录自动留备份）；同版本重复运行秒过。注意修复装在新安装器 exe 内，统一修复后首个包需手动运行一次完成覆盖，之后一劳永逸。
- **状态**：代码已修复（build + 106 测试全绿），待总装后手测。
- **本次临时绕过（已执行）**：杀掉桥进程 → 旧 `current` 目录改名备份（`E:\livedotmap\.previous-manual-20260816`）→ 重跑安装器完整复制成功。

### 2. 箭头工具点击节点，方案箭头「卡在圆圈周围」抽风
- **现象**：箭头工具点击节点，时而正常弹出一条方案箭头，时而箭头极短、整条压在圆圈底下，只剩半个标签在圆边若隐若现。
- **根因**：`app.html:1958` 拉线/弯折拖拽在第一个 pointermove 就无条件 `drag.moved = true`，没有节点/便签拖拽那样的 4px 死区（对比 `app.html:1989`、`1996`）。点击时手部 1~2px 抖动被误判为拖拽，箭头终点落在圆圈内（短于半径）→ 线被圆圈盖住。「点击未拖动自动生成默认长度箭头」的兜底分支（`app.html:2074-2079`）形同虚设。
- **方案**（已确定）：拉线/弯折拖拽创建时记录按下点 `sx/sy`，pointermove 加同样的 4px 死区，未超过阈值不算 moved、不更新终点。顺带治好「点击已连接线末端手柄时手抖误脱钩」的同源暗病。
- **改后效果**：点节点稳定弹出 ~155px 默认箭头、方向自动避开已有线 ≥30°；按住拖出仍可自由自定义，行为不变。已生成的「桩线」属数据残留，修复后手动删除或统一清理。
- **状态**：代码已修复（build + 106 测试全绿），待总装后手测。

### 3. 画布内移动鼠标，光标有时「全透明」看不见
- **现象**：箭头工具下在空白处移动，光标持续消失；节点/标签上又能看见。
- **根因**：非代码 bug——用 `output/cursor-test.html` 六格光标测试页实机验证：**crosshair（2 号）与 text（5 号）两种细线光标在该机几乎不可见**（文字上有反色衬底才勉强可见），default/pointer/grab 等粗光标正常。即 Windows 系统层细线光标渲染问题（高 DPI/缩放下过细过淡）。画布箭头/节点工具的空白处恰好用 crosshair，故「消失」。
- **方案（已确定：方案 B）**：工具模式不再依赖系统 crosshair——统一默认箭头光标 + **画布自绘跟随鼠标的十字准星**（DOM 元素，两条细线+中心圈，跟随指针，不经过系统光标渲染，任何机器稳定可见，可用品牌淡紫色）。行内编辑的 I 型光标不动（编辑态有输入框+caret，影响小）。
- **改后效果**：箭头/节点工具下任何机器都能看到清晰准星；光标消失问题根除，且不再受用户系统光标渲染差异影响。
- **状态**：代码已修复（build + 106 测试全绿），待总装后手测。

### 4. 悬浮上面节点、拖动却动了下面的节点（+ 节点重名「新节点1」）
- **现象**：箭头工具新建两个节点，悬浮在上面节点拖动，实际移动的是下面的节点；两个节点还重名「新节点1」。
- **根因（双层）**：
  - A. **counters 永不同步**：画布保存走 `diffDocument`（`src/web/bridge-client.ts:61-64`），只发 collections + `set_meta`（仅 name）+ `set_view` + `set_ui`，**从不携带 counters**；桥端 `set_meta` 也只认 name（`src/shared/index.mjs:384`）。结果 `map.json` 里的 counters 永远停在模板初始值。实锤：用户当前 `map.json` 的 counters 是 `{num:2, nodeName:1}`，而节点已排到 n4/新节点3。
  - B. **deserialize 盲信 counters**：`app.html:2263-2266` `c.num ?? 兜底` —— counters 存在但过期时，安全的「按现有数据推导」兜底不会触发。重新加载/Agent 同步后 `nextNum` 回退到 2 → 新节点 id `n2` 与现有节点**撞号**；`nextNodeName` 回退到 1 → 重名「新节点1」。
  - 撞号后：两个 DOM 元素同 `data-id`，`nodeById`（Map 后者覆盖前者）解析到另一个节点 → 拖上面的动下面的；且两个节点共用同一个 `.live-dot-map/nodes/n2.md`，前后端联动必然错乱。edge/ann/routeName 计数器同病（`counters.edge=1` 而线上已有 e1~e8，再拉线必撞 e1）。
- **方案**（已确定）：
  1. 客户端自愈（主修）：`deserialize` 把所有计数器钳制到「不低于现有数据推导值」——`nextNum = max(c.num, 最大num+1, 最大id后缀+1)`，`nextNodeName = max(c.nodeName, 已用「新节点N」最大N+1, 节点数+1)`，edge/ann/edgeName/routeName 同理。无协议改动，过期 counters 直接失效。
  2. （可选，二期）协议层补 counters 同步通道（如扩展 `set_meta` 或新增 `set_counters` op），让 map.json 计数器保持新鲜。
  3. 存量撞号数据：启动自检发现重复 id 时报错提示或自动重编号（可选）。
- **改后效果**：刷新/同步后新建节点、拉线不再撞号重名；拖动哪个节点就动哪个；节点与 Markdown 文件一一对应，联动恢复正常。
- **状态**：代码已修复（build + 106 测试全绿），待总装后手测。

### 5. 双击节点重命名时圆圈消失，只剩裸输入框
- **现象**：双击圆形节点重命名，圆圈整个消失，原地变成一个带边框的输入框，观感奇怪。
- **根因**：`editNodeName`（`app.html:1449`）进入编辑时设置 `inlineNodeEdit`，渲染函数 `app.html:997` 对编辑中的节点**跳过重建**（原意「避免重影」），而 `app.html:986` 每次重绘先删掉全部节点 DOM——于是编辑期间节点被移除，只剩悬浮输入框。
- **方案（已确定，Excalidraw 式）**：编辑中节点照常渲染圆圈，仅隐藏圆内文字（`editing` 类 + `visibility:hidden`）；输入框叠加在圆心、透明无边框、字号对齐圆内文字——视觉上就是「圆圈里直接改字」。提交后半径按新文字自动重算（现有逻辑保留）。
- **改后效果**：双击节点后圆圈始终在，文字原地可编辑，与 Excalidraw 一致。
- **状态**：代码已修复（build + 106 测试全绿），待总装后手测。

### 6. 双击方案线不能重命名，还容易误弯线
- **现象**：双击方案线想重命名没反应，只有精确双击方案名文字才行；而名字正下方就是中点弯折手柄（紫点），经常误点到它把线弯了。
- **根因**：双击重命名只挂在 `<text>` 元素上（`app.html:2144`）；双击线身 path 走「弯折拖拽」入口（`app.html:1892-1903`）无重命名；中点手柄正好压在标签下方，且拖拽无 4px 死区（与问题 2 同根因），手抖即弯线。
- **方案（已确定，Excalidraw 式）**：双击线身任意位置（含中点手柄、含命中区）都打开方案名重命名输入框，定位到标签处；弯折保留，但只在「按住拖动超过 4px」时触发（依赖问题 2 的死区修复，双击天然零位移，永不误弯）。
- **改后效果**：双击线=改名，拖中点=弯线，两个动作不再打架。
- **状态**：代码已修复（build + 106 测试全绿），待总装后手测。

### 7. 项目选择器老式且弹到画布后面 + 「工作区」菜单概念混乱（引出两级结构重构）
- **现象**：① 点「选择其他项目」弹出的是 Win95 式树形对话框（Browse For Folder），且出现在画布窗口**后面**，不最小化画布根本看不见；② 「工作区」子菜单把「新建空白地图」和项目切换混在一起——选项目和新建地图是两个概念；③ 菜单无搜索、最近项目只显示名称（同名文件夹分不清）。
- **根因**：
  - 选择器：`src/bridge/server.mjs:46-64` `pickProjectFolder()` spawn 隐藏 PowerShell 调 WinForms `FolderBrowserDialog`（老式控件），`ShowDialog()` 无 owner 窗口、进程 `windowsHide:true`，对话框挂桌面，Z 序排在 Chrome 之后。
  - 菜单：`app.html:1722-1735` `buildProjectMenu()` 把「新建空白地图」塞进「工作区」子菜单；`openMenu`（`app.html:1173`）只支持按钮/分隔线/标题，做不了搜索框。
  - 架构：当前**一个项目 = 一张地图**写死——`.live-dot-map/map.json` 单文件（`app.html:2344`、`src/bridge/project-store.mjs:69`），而产品的既定需求是「一个项目多张地图，每张是一个任务的记忆，选定一张作为 Agent 默认读写」。
- **方案（已确定，分三部分，本轮全部实施）**：
  - **A. 顶栏两级入口**（替代现「工作区」菜单项）：顶栏改为两个独立控件——**项目名按钮**（📁，点击开弹层：搜索框 + 最近项目列表（名称+路径）+「选择其他项目…」）与**地图名按钮**（🗺，点击开弹层：当前项目的地图列表（名称+更新时间+当前标记）+「新建地图」）。命名就叫「项目」「地图」，不造新词。**tooltip 只写用户要做的核心动作，几个字，禁止罗列弹层功能、禁止解释次要功能**（对标 Codex「选择一个项目来运行聊天」）：项目按钮 = 「选择项目」，地图按钮 = 「切换地图」。解释性文案一律不进常驻界面。
  - **B. 选择器现代化 + 置顶**：桥端 `pickProjectFolder()` 改用 `IFileOpenDialog`（FOS_PICKFOLDERS，PowerShell `Add-Type` 嵌 C# COM 互操作，无新依赖）——即 VS Code/Codex 同款现代选择文件夹对话框；创建 `TopMost` 隐形 owner 窗体传句柄，保证永远弹在画布之上。失败兜底回落 `FolderBrowserDialog` 但同样挂置顶 owner。无桥模式走 `showDirectoryPicker()` 原生选择器，不受影响。
  - **C. 多地图架构**（既定需求，不是新提案）：
    - 存储：`.live-dot-map/maps/<地图id>/` 每图一个目录，内含自己的 `map.json` + `routes/` + `nodes/` 分片（id 做目录名，重命名只改 json 的 name；分片按图隔离，跨图 id 撞号无所谓）。当前地图指针存 `.live-dot-map/active-map`。
    - 迁移：打开老项目自动把 `map.json` + 分片目录挪入 `maps/default/`（先备份到现有 `backups/`），写好指针，无感升级。
    - 桥：`project-store` 数据目录参数化到当前地图目录；新增 列地图/切地图/新建/重命名 接口；文件监听跟随当前地图。
    - 协议：走桥 API 的 Agent 零改动；直读文件的，agent-kit 改为「先读 `active-map` 指针再读图」，同步 `docs/agent-protocol.md` 与 `docs/map-json-v2.md`。
    - 前端：IO 层指向当前地图文件，切图即重载，轮询跟随。
- **实施顺序**：先修问题 1~6 小项与 A/B，最后做 C（架构项），保证中途任意时刻前面的修复都稳定可用。
- **改后效果**：选择器是现代资源管理器式对话框、永远弹在最前；两级结构一目了然（项目=文件夹存所有数据，地图=单任务记忆、Agent 默认读写当前张）；「新建地图」归位地图组，不再和项目切换混放。
- **状态**：A/B/C 全部代码完成（build + 113 测试全绿）。C 已落地：`.live-dot-map/active-map` 指针 + `maps/<id>/` 每图独立目录（map.json、分片、.bridge 按图隔离）；老项目经桥打开自动迁移到 `maps/default/`（先备份）；桥新增 列地图/新建/切换/重命名 四个 API；前端地图弹层为真列表（名称+更新时间+当前标记），「新建地图」不再覆盖。待总装后手测。

### 8. 右下「接入 Agent」按钮与设置抽屉整体无用，且「连接状态」是假信号
- **现象**：右下常驻「接入 Agent」按钮，点开是一个设置抽屉（接入当前 Agent / 连接状态 / 安全边界 / 数据），用户从未用过，直觉没用。
- **根因（核实结论）**：
  - 按钮（`app.html:376` + `app.html:2198`）唯一动作是打开抽屉，无独立功能。
  - 抽屉四块内容：`接入当前 Agent`（桥已连时只弹 toast「当前协作已就绪」，未连时就是选项目——与问题 7 顶栏项目入口重复）；`连接状态` 列表 JS 是活的（`src/web/bridge-client.ts:282-302` 拉 `/api/v1/agents` 填列表）但 CSS `.agent-status-list{display:none}`（`app.html:269` 覆盖了上一行的 grid）**永久隐藏，是死 UI**；`安全边界` 纯静态文字；`数据/工作区` 是第三次重复的项目选择入口。
  - 更本质的：「连接状态」是**静态推断不是真实连接**（`src/bridge/server.mjs:762-790`）——只看 CLI 可执行文件是否存在 + 项目适配配置是否写入 + 信任是否确认；Agent 此刻跑没跑、在不在读写完全不知道，没启动的 Agent 也显示「已连接」。唯一真实信号是 `agent-health.json`（`server.mjs:133-144`）：Agent 真的通过 MCP/hook 调桥时桥会记一笔（谁/何时/事件/成败）。
- **方案（已确定）**：
  1. 删除右下「接入 Agent」按钮、整个设置抽屉、左上菜单的「设置」项。
  2. **不做** Agent 状态圆点——静态推断的「已连接」比没有更误导。
  3. 只保留真实信号：顶栏保存状态点的 tooltip 加一行「Agent 最近写回：N 分钟前（agent 名）」（数据源 `agent-health.json`），无记录则不显示。
  4. 「安全边界」静态说明挪入新手引导一页，不占常驻界面。
- **改后效果**：画布右下角干净；项目选择只剩顶栏一个入口；「Agent 有没有真的在协作」由真实写回记录回答，不靠配置文件猜。

### 11. 切换项目后顶栏项目名不更新（仍显示 workspace）
- **现象**：在项目弹层点了「壁纸制作」，画布内容其实已切换，但顶栏项目名仍显示 workspace，弹层里「当前」标记也还在 workspace 上。
- **根因（核实结论）**：桥模式 `currentProjectRoot()`（`app.html:1701`）优先读 URL 的 `?project=` 参数，其次才读 sessionStorage；而切换项目时 `attachProject`（`src/web/bridge-client.ts`）只更新了 sessionStorage，URL 还是启动时的旧项目，于是显示永远停在启动项目上。同链路初始化（`bridge-client.ts:153`）也是 URL 优先，刷新后会重开旧项目。
- **方案（已确定）**：`attachProject` 里同步用 `history.replaceState` 把 URL 的 `?project=` 改成新项目——URL 本来就是唯一权威来源，改它一处，顶栏显示、弹层当前标记、刷新重开全部自然正确。
- **改后效果**：切项目后顶栏立即显示新项目名，弹层「当前」标记跟对，刷新/重开停留在切换后的项目。
- **状态**：已修复（build + 113 测试全绿），已重装到 `E:\livedotmap\current`（备份 `.previous-manual-20260816214438`），待手测。
