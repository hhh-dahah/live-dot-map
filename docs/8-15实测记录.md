### 核实情况

1. **安装器确实是自研的**：`installer/winforms/`（C# WinForms，`LiveDotMapSetup.csproj` + `Program.cs`，约 880 行），没有用 Inno Setup / NSIS / WiX 等现成安装框架；界面由 `LauncherForm` 单窗口承载。
2. **单页堆功能属实**：`LauncherForm` 布局 = 标题 + 副标题 + 安装父目录输入框（"更改设置"）+ 5 个操作按钮（安装并打开画布 / 打开画布 / 修复 / 更新 / 卸载（保留地图）/ 打开安装位置）+ 状态日志。安装、启动、修复、卸载、浏览全部混在首屏。
3. **功能错位属实**：这些维护操作由同一 exe 承担，因为安装器采用"自拷贝"模式——把自身完整目录复制到 `livedotmap\current`，同一 exe 兼作安装器与产品入口（`--open` 参数进入 `ProductLauncherForm` 打开画布；桌面/开始菜单快捷方式已带 `--open`）。
4. **UAC：不是漏掉，是刻意设计**：`app.manifest` 明确 `requestedExecutionLevel="asInvoker"`（不申请管理员）。安装只写当前用户目录（默认 `%LocalAppData%\livedotmap`），不需要管理员权限；QoderWake 装到 `C:\Program Files` 所以需要 UAC。目标形态（goal.md、8-14 台账）也写明"不请求管理员权限"。per-user 安装不弹 UAC 是常见现代做法（VS Code user 版、Notion 等），不是缺陷。
5. **对照差异总结**：大厂是经典多步向导（选路径 → 开始菜单 → 附加任务 → Install → Finish，Back/Next/Cancel）；我们是一页流（路径 + 全部功能按钮 + 日志）。两者都是合法形态，但当前单页把"安装前选择"与"安装后维护"两类功能混在同一界面，且没有任何分步引导。

### 待汇总问题

- [ ] P1 流程形态：安装界面需要明确"安装前"与"已安装"两种状态，分阶段呈现；首次安装只展示安装所需（位置 + 安装按钮），不展示维护功能。
- [ ] P1 功能边界：打开画布 / 修复 / 更新 / 卸载 / 打开安装位置不应作为安装器首屏功能；打开画布已由 `--open` 产品启动器承担，维护功能应移出首屏（卸载建议注册到 Windows 设置→应用，当前无注册表卸载项）。
- [ ] P3 认知澄清：UAC 不弹是 per-user 安装的设计选择，不是遗漏；是否要在安装页说明"不申请管理员权限"的文案待定。
- [x] 已决策（2026-08-15）：用户确认极简单页分状态方案（未安装 → 安装页；已安装 → 直接打开画布），不采用经典多步向导；更新入口进产品本体（见记录 03）。

### 截图路径

- Codex 桌面应用（参考更新入口形态）：`C:\Users\Thomas\Documents\ShareX\Screenshots\2026-08\ChatGPT_LDnPerzAlW.png`（Codex 界面：左侧导航/项目列表、主聊天区、左下角用户头像与角落小图标区、底部输入栏——更新入口为角落小图标风格）
- 活点地图画布界面（当前形态）：`C:\Users\Thomas\Documents\ShareX\Screenshots\2026-08\chrome_u43eQC7qr9.png`
  - OCR 关键元素：左上"壁纸制作 + 已保存（绿点）"、顶部中央工具栏（H 手掌 / Y 选择 / N / L / M）、左下缩放 141%、右下"接入 Agent"、画布有红色问题节点"454"、白色节点"开始"、紫色"主路线"标签

### 核实情况

1. **"更新在安装器里"属实**：更新/修复逻辑（`UpdateInstalledAsync`：复制新 payload → 校验 → 备份 `current` → 切换）只存在于安装器 `installer/winforms/Program.cs` 的 `LauncherForm`；画布（`app.html`）与桥（`livedot.mjs`）没有任何版本检查或更新入口。
2. **左上角汉堡菜单已存在，方案有落点**：`app.html` 已有 `#proj-menu-btn`（左上项目按钮）+ 通用菜单 `openMenu()`（现有项：重命名地图、打开项目文件夹、设置等）；加"检查更新 / 更新到 x.y.z"菜单项与红点徽标技术上直接可行。
3. **版本源与检测路径**：
   - 本地版本：`payload-manifest.json` / `package.json` 的 `version`。
   - 线上版本：`.deploy/release-manifest.json`（`build-release-manifest.mjs` 生成，含版本与 hash），通过 `livedotmap.top` 分发——检测更新即拉取线上 manifest 与本地版本比对。
   - **CSP 约束（关键）**：`app.html` 的 `connect-src` 只允许 `'self'` 与 `http://localhost:* / 127.0.0.1:*`，前端不能直接 fetch 线上地址；更新检查必须由本地桥（Node 侧，无此限制）提供接口代查。
   - 桥现有 API（health/session/projects/open/snapshot/commands/events/recover/agents/markdown/reveal/mcp）**没有版本检查与更新接口**，需新增（如 `/api/v1/update/check`、`/api/v1/update/apply`）。
4. **更新执行链路**：桥进程运行时其 exe（`livedot-bridge-win-x64.exe`）被文件锁占用，替换 payload 必须先停桥；可复用安装器现有"备份 + 校验 + 切换 `current`"逻辑（给 `LiveDotMapSetup.exe` 加 `--update` 参数）：检查 → 下载新包 → 用户确认 → 停桥 → 更新器替换 → 重新打开画布。
5. **"回到之前的界面"可行**：地图视图（缩放/平移）已通过 `set_view` 持久化在 `map.json`；画布 URL 带 `project` 参数；未保存改动由 WAL/原子保存保障——重启后重新打开同一项目 URL 即回到之前的视图与内容。

### 方案结论（用户已确认方向，进入待办）

- [x] 用户确认：极简安装方向；更新入口放产品本体。
- [ ] P1 产品内更新入口：左上角汉堡菜单，检测到新版本时按钮显示红点，菜单内提供"更新到新版本"项；无更新时保持简洁（可提供"检查更新"与版本号显示）。
- [ ] P1 更新链路：桥新增更新检查/应用接口（绕过前端 CSP）；复用安装器备份-切换逻辑完成 payload 替换。
- [ ] P1 自动重启恢复：更新完成后自动重启桥并重新打开画布，恢复到用户之前的项目与视图。
- [ ] P2 更新提示频率：打开画布时检查一次 + 手动检查；更新时明确提示"将重启画布"，由用户确认。

### 截图路径

- `C:\Users\Thomas\Documents\ShareX\Screenshots\2026-08\dwm_UFeY7UmR8d.png`
  - OCR 关键信息：标题"活点地图（未响应）"；日志 `[15:18:18] 安装包已校验：版本 2.0.0。...`、`[15:57:12] 软件将安装到：D:\桌面\活点地图\live-dot-map\ui设计 html\dist\windows-installer\livedotmap`、`[16:03:54] 正在复制并校验本地程序文件...`

### 核实情况（根因已定位）

1. **UI 线程被同步大文件复制阻塞（主因）**：`EnsureInstalledAsync`（Program.cs L531-532）调用 `CopyDirectory(SourceRoot, temporary)`（L875-880），内部是**同步** `File.Copy` 递归循环，在 UI 线程直接执行、没有 `await`——复制期间 WinForms 消息泵完全停摆，窗口立即显示"未响应"。
2. **复制量约 340MB+**：源目录（安装包所在目录）含 161MB 的 `LiveDotMapSetup.exe` + `payload\`（92MB 桥 exe + app.html + icons + skill 等）；用户选择的父目录正是安装包所在目录，目标 `livedotmap\current` 成为源目录的子目录，复制量翻倍（temporary 也在其下）。
3. **慢的因素叠加**：D 盘复制 340MB+ + Windows Defender 对新 exe 的实时扫描 + 复制后 `PayloadVerifier.Verify` 再对 payload 全量做 SHA256（再读几百 MB）。整个过程无任何进度输出（只有一条静态日志），窗口又显示"未响应"，用户只能认为卡死。
4. **8-14 装 C 盘没被察觉的原因**：目标是 `%LocalAppData%`（C 盘 SSD），几百 MB 复制 + 校验约几十秒内完成，UI 短暂无响应未被注意；本次 D 盘 + 源目录嵌套场景把问题放大到可见。

### 待汇总问题

- [ ] P1 安装进度与响应：复制/校验改为后台线程执行（UI 不阻塞、窗口不再"未响应"），按文件或字节实时显示进度（如"正在复制 3/9：livedot-bridge-win-x64.exe（92MB）"），完成前窗口始终可交互。
