## 一、PPT 10 页逐页文案

### 第 1 页 · 封面
- **主标题**：活点地图
- **副标题**：让人和 Agent 在同一张地图上探索未知
- **配图**：进度可视化.png 淡化作背景，或 landing-hero.png
- **备注**：一句话开场——「聊天适合推进一条路，地图适合管理很多条路」

### 第 2 页 · 问题
- 标题：为什么线性聊天不适合没有标准答案的探索任务
- 要点：
  1. 探索型任务天然分叉：方案并行、暂停、失败、重新比较，聊天记录是线性串，装不下这张网
  2. 失败原因随会话淡忘——「为什么没选它」再难查证
  3. 换 Agent、隔几天回来，上下文要全部重讲

### 第 3 页 · 真实案例
- 标题：一个真实场景：AI 壁纸的多路线并行探索
- 要点：
  1. 同一个目标「做出更好的壁纸」，同时有换模型 / 换 LoRA / 改提示词 / 改工作流多条路线
  2. 这些路线会分叉、暂停、失败、重新比较——不是线性推进
  3. 活点地图把每一条路线长期保留，不让它们淹没在聊天记录里
- 配图：canvas-map.png（多路线三态演示图）

### 第 4 页 · 产品方案
- 标题：节点、方案线、分叉、状态——一张可读的探索地图
- 要点：
  1. 节点 = 目标 / 问题 / 结果；方案线 = 一次具体尝试
  2. 三态一目了然：绿色实线 = 已验证成功，红色虚线 = 已验证失败，灰色点线 = 待验证
  3. 路线可分叉、可悬空、可回溯；状态与连接解耦，改状态不动结构
- 配图：进度可视化.png（本页实拍：五节点 + 三态线 + 问题徽标 + 分叉）

### 第 5 页 · 核心创新
- 标题：不是只读 Dashboard——人和 Agent 双向操作同一张图
- 要点：
  1. 人可以：建节点、标注问题、否定方案、修改路线、选择节点继续讨论
  2. Agent 可以：读取节点上下文、提出多个方案、创建路线、把结果写回地图
  3. 任何节点可一键复制引用交给 Agent——精确寻址「这一块问题」，无需重述上下文
- 配图：canvas-note.png（节点+便签）

### 第 6 页 · 实际 Demo / 当前完成度
- 标题：真实使用——Agent 正在用活点地图协作
- 要点：
  1. 截图即实拍：让 Agent「用活点地图展示项目进度」，Agent 读地图后生成进度路线（revision 2）
  2. 五阶段推进：v2 核心完成 → 8-16 统一修复完成 → 人工验收中 → 公开发布门禁
  3. Agent 自己指出「方案详情 Markdown 尚未建立，验证提示缺少过程证据」——证据闭环真实生效
- 配图：进度可视化.png（大图，本次提交的主证据图）

### 第 7 页 · 技术架构
- 标题：本地文件 + Markdown + 地图索引 + Skill/Agent 接口
- 要点：
  1. 单一事实源：`.live-dot-map/map.json` 索引 + nodes/routes Markdown 分片；人机读写同一组文件
  2. Agent 接入：10 个固定 MCP 工具 + 官方 Skill（live-dot-map）+ 四套适配器（Claude Code / Codex / Kimi Code / CodeBuddy）
  3. 本地优先：全部数据在项目目录，无云端依赖，MIT 开源
- 配图：canvas-panel.png 或 canvas-loaded.png

### 第 8 页 · GOAI 比赛适配
- 标题：Planner / Executor / Verifier 三 Agent + AgentTeams 适配层
- 要点：
  1. 三个不同职能 Agent：Planner 任务拆解与路线分配、Executor 方案执行与工具调用、Verifier 结果验证与证据检查
  2. 三 Agent 以 AgentTeams 为协同框架，通过活点地图的 MCP/Skill 接口读写同一份状态与证据
  3. 活点地图提供共享状态层：上下文传递（节点引用+标注送达）、状态追踪（三态+里程碑+revision）、执行证据沉淀
- 配图：AgentTeams 映射小表（角色编排=路线 / 拆解=问题路线 / 传递=引用+标注 / 追踪=三态+revision）

### 第 9 页 · 安全 / 异常 / 人工介入
- 标题：判断权永远在人
- 要点：
  1. 人可以标注、否定方案、重新选择路线；Agent 的修改全部可溯源（createdBy / revision）
  2. 危险操作确认：删除仅限人类、里程碑需人工审核（Agent 无法伪造 human 确认）
  3. 失败保留：失败方案不删除、可归档；WAL 全量审计，可恢复、可回滚
- 配图：canvas-loaded.png 或进度图局部

### 第 10 页 · 开源与下一步
- 标题：从完整产品到多 Agent 生态
- 要点：
  1. 下一步路线：完整产品打磨 → 开源发布 → AgentTeams 适配 → 多 Agent Demo
  2. 开放成果：文件协议（map.json v2）+ MCP 工具契约 + Skill 模板 + 四套适配器
  3. 长期愿景：任何 Agent，只要理解文件协议，就能接入同一张探索地图
- 配图：路线图时间轴（4 步箭头）

## 二、录屏脚本（约 90 秒，口播稿）

**开场原则**：不展示 Landing Page 和新手引导，直接进已准备好的项目地图。

| 秒 | 画面 | 口播（照着念即可） |
|---|---|---|
| 0–8 | 打开 app.html，直接进入演示项目地图（多分支） | 「这是活点地图——人和 Agent 共享的探索地图。先看画布：多条探索路线同时存在。」 |
| 8–20 | 鼠标划过三色方案线，放大展示 | 「绿色实线是已验证成功的方案，红色虚线是失败方案——失败不会消失，灰色是待验证。每次尝试都留在图上。」 |
| 20–35 | 选一个节点，右键「添加标注」，写一条标注（如「先验证 A 方案，B 暂时放下」） | 「我在这条路线上留一条标注，告诉 Agent 我的判断。」 |
| 35–50 | 展示该节点的 Markdown：打开详情，滚动两秒 | 「每个节点背后都有完整上下文——记录在项目里的 Markdown 文件里，画布只放结构和状态。」 |
| 50–65 | 复制节点引用，粘贴给右侧 Agent；Agent 读引用、回应定位正确 | 「把这个节点复制成引用交给 Agent。Agent 不需要重读整个项目——它精确知道说的是哪一个问题、之前试过什么。」 |
| 65–80 | Agent 提出新方案，写回地图；画布刷新出现新方案线/标注已读 | 「Agent 的方案直接反映回地图——人机双方操作同一张图，同一份记忆。」 |
| 80–90 | 结尾定格封面句 | 「聊天适合推进一条路，地图适合管理很多条路。活点地图。」 |

**录屏要点**：
- 第 6 步若本地桥 + 真实 Agent 会话可用，直接录真实写回（画布自动刷新）；若不可用，演示「复制引用」动作 + 引用文本即可，勿造假
- 全程 90 秒内，右上角可叠加「本地优先 · Agent 无关 · 判断权在人」三词字幕
- 分辨率 1920×1080，画布提前 fitView 到最佳视野
