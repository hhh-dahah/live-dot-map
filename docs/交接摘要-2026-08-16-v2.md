## 项目是什么

人和 Agent 共享的探索地图：圆形节点写目标/结果，三色方案线记尝试（绿实线=成功、红虚线=失败、灰点线=待验证），详细内容存本地 Markdown 分片。本地优先：数据全在项目文件夹的 `.live-dot-map/` 里，人和本地 Agent 读写同一组文件。交付物是单文件画布 `app.html` + 零依赖本地桥 `livedot.mjs`；Windows 分发为 WinForms 单 exe 安装器（~187MB，内嵌 payload 与 SEA 桥，8-17 起真正单文件化）。

## 数据与协议（多地图版）

```
项目文件夹/.live-dot-map/
  active-map            # 当前地图 id（一行文本，缺省/非法回退 default）
  maps/<地图id>/
    map.json            # v2 文档，顶层有 mapDir 字段
    nodes/ routes/      # Markdown 分片，路径以 mapDir 为前缀
    .bridge/            # wal/snapshots/backups/quarantine，按图隔离
  .bridge/agent-health.json   # 项目级 Agent 真实写回记录
```

- 协议权威文档：`docs/map-json-v2.md`（数据）、`docs/agent-protocol.md`（Agent 协议）。直读文件的 Agent 先读 `active-map` 指针；走桥 API 的 Agent 零改动。
- 桥新端点：`GET /maps`、`POST /maps/create|switch|rename`；存储与事件按 `root::mapId` 分键。
- 迁移注意：旧 `wal.ndjson` 迁移后改名 `.legacy-migrated` 留证不再用（有意决策，原因见 `implement.md` 8-16 多地图节）。

## 工程要点（别踩坑）

- `app.html` 是源也是构建产物，`npm run build` in-place 重写它；但 `window.LiveDotApp` 集成逻辑（load/setStatus 等）的权威源在 `scripts/build-app.mjs` 的 `appIntegration()`，手改 app.html 该段会被覆盖。
- 桥客户端在 `src/web/bridge-client.ts`，打包进 app.html；改它必须 `npm run build` 才生效。
- 改 agent-kit/SKILL 后跑 `npm run sync:agent-skill`（同步 5 个分发副本）。
- 重建安装包：`npm run build:windows-installer`（需 dotnet，`/c/Program Files/dotnet`）；**先杀 `livedot-bridge-win-x64.exe`** 否则 EBUSY；产物在 `dist/windows-installer/`。
- 测试基线 113 全绿；测试用 `LIVEDOT_*` env 隔离，别碰真实 `~/.live-dot-map/`。
- 偶发「user-mapped section」文件锁导致 build 失败，重试即可。
- 文案：简体中文全角标点；tooltip 只写核心动作几个字；术语表见 `docs/8-16文案修改建议.md`（项目/地图/目标/成功，禁用「工作区」）。
- 桌面快捷方式 `D:\桌面\活点地图.lnk` → `E:\livedotmap\current\LiveDotMapSetup.exe --open`，跟随安装目录不用管。
