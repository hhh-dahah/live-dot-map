# UX 文案审查报告(2026-08-16)

> 依据 ux-writing 技能(content-designer/ux-writing-skill)的四项质量标准审查:**目的性 / 简洁 / 对话感 / 清晰**,辅以错误消息模式、空状态模式、可访问性与句长基准。

## 三、亮点(应保持的写法)

1. **后果式确认文案**(高利害操作讲清后果,不操纵):
   - 更新确认:"更新需要重启画布,已保存的内容不会丢失。是否现在更新?"(`app.html:1670`)
   - 卸载说明:"将删除本地程序与快捷方式,项目文件夹中的地图和 Markdown 会保留。"
   - 归档按钮:"归档此方案(弱化显示,不删数据)"——动作+后果,教科书级。
2. **安装器预答顾虑**:"安装只写入当前 Windows 用户选择的位置,不请求管理员权限""不会在安装阶段写入项目"。
3. **空状态带行动指引**:"从一张地图开始"+ 三个选择各配一句说明;便签空占位"输入标注"。
4. **成功消息带 reassure**:"已加载简单示例(不会读取项目文件)""整理已应用,历史方案已保留"。
5. **隐私主张一句话**:"本地优先:文件都在你自己的文件夹里,不上传任何服务器。"
6. **评分帮助文本**:"0–100,留空即未评"——极简且完整。
7. **教程的口语人格**:"走通了顺手打个分(0–100),以后一眼看出哪条最值"——合适的场合出现合适的个性。
8. **颜色多模态表达**:教程用文字解释"绿=走通,红=失败,灰=待验证",不依赖颜色单独传达含义,符合可访问性要求。

## 四、问题清单

### P0 事实准确性(必须修,文案与行为不符)

**A1. 教程说"滚轮缩放",实际滚轮是平移**
- 位置:`app.html:2634`(三分钟上手第 1 条)"滚轮缩放,空格或中键拖拽平移"
- 实际行为:`app.html:2129-2133` 普通滚轮=平移画布,Ctrl/⌘+滚轮=缩放;工具提示 `TOOL_HINTS.hand`(1621 行)写的"滚轮/中键平移"才是对的。
- 建议:"Ctrl+滚轮缩放,滚轮或中键平移画布,空格拖拽也可平移。"

**A2. 引导用户去点一个不存在的菜单项**
- 位置:`app.html:2532` "点左上项目菜单「打开项目文件夹」继续上次项目"
- 实际菜单标签已改为"选择其他项目…"/"连接项目文件夹…"(`app.html:1724-1725`);`agent-kit/index.html:69` "菜单里选「打开项目文件夹」"同样过时。
- 建议:统一改为现名"连接项目文件夹…"或"选择项目…"。

**A3. "删除节点与路线前需确认"与画布实际行为不符**
- 位置:`app.html:421`(设置抽屉·安全边界)
- 画布里人删除节点/方案是立即执行(靠撤销兜底,`app.html:1320`),并无确认;该句更像描述 Agent 协议侧约束。
- 建议:改为指代明确,如"Agent 删除前需经你确认;你手动删除可随时撤销"。

### P1 一致性(同类问题成批,建议一次清理)

**B1. 中英文标点混用(半角/全角)**——最大的系统性问题,直接违反"清晰-术语与模式一致":
- 半角冒号/逗号/问号/括号(旧文案):`app.html:2353` "并连接:"、`2360` "项目文件夹:"、`2365` "读不懂(文件可能损坏),"、`2391` "演示模式:改动只在本页,"、`2395` "保存失败:…("、`2203` "覆盖当前 map.json?"、`2479` "不存在,创建它吗?"、`2446` "只认 .json 地图文件"、`1784` "需要 Chrome 或 Edge;"、`2320` "继续扩张"、`2406/2420/2430/2450` 等
- 全角(新文案,正确):整理对话框、Markdown 编辑器、桥接脚本(`:…?()`)
- agent-kit 页整页半角;落地页整页全角。
- 建议:全站统一简体中文全角标点(冒号:、逗号,、问号?、括号()),对英文与代码片段内部保留半角。

**B2. 同一事物两个名字:"标注" vs "便签"**
- 工具栏/菜单/面板用"标注"(`app.html:355/1316/1085`),教程用"便签"(2634 行"M 加便签"),落地页功能 2 标题"便签、评分,结论随手留下"。
- 建议:选定"标注"(产品内主流)后全局替换,教程与落地页同步;或反向统一为"便签",二选一。

**B3. "回忆" vs "记忆"**
- 落地页 hero 副标题"探索 记录 回忆"(page.tsx:62),其余全部用"记忆":落地页"你的项目,你的记忆/同一份探索记忆"、抽屉"同一份本地记忆"、产品文档"记忆系统"。
- 建议:hero 改为"探索 · 记录 · 记忆",与全站术语对齐。

**B4. "无法" vs "没能"**
- `app.html:2339` "没能打开文件夹:";其余错误均为"无法…"。
- 建议:统一"无法"。

**B5. 落地页页脚分组标题用英文**
- "Explore / Product / Contact"(page.tsx:163-175)下挂中文链接,与 zh-CN 全中文页面冲突。
- 建议:改"功能 / 产品 / 联系"。

**B6. "工作区 / 项目文件夹 / 项目"三词并用**
- 抽屉"数据→工作区"(426 行)、toast"已连接项目文件夹"(2360)、菜单"工作区"子菜单里是"选择其他项目…/新建空白地图"(1722-1733)、首启引导"选择项目…"。
- 建议:确定主术语(建议"项目",设置里可保留"工作区"一词但需在文案中点明两者同义),避免用户以为是三种东西。

### P1 清晰度(句子本身的问题)

**C1. 循环表述,信息量为零**
- `app.html:412`:"连接后,地图和当前 Agent 使用同一份本地记忆;**未连接时不会显示已连接**。"
- 后半句是废话式否定。建议:"连接后,地图和当前 Agent 使用同一份本地记忆;未连接不影响画布使用。"

**C2. agent-kit 第 1 步注释是一堵文字墙**(index.html:51)
- 一段话塞了三件事:备用域名(两个长 URL)、全自动会做什么、旧记录迁移。不符合"可扫描分块"。
- 建议拆成:"拉取失败?→ 备用地址两个;全自动流程会:下载画布、建快捷方式、注入协议、初始化地图;已有记录会转为草稿,由你在画布审核。"用列表呈现。

**C3. 电报式残句**
- "让 Agent 全自动**接**(推荐)"、"或者手动**接**"(agent-kit:48/55)——动词被裁掉宾语。
- 建议:"让 Agent 全自动接入(推荐)""或手动接入"。
- "只认 .json 地图文件"(`app.html:2446`)——建议"只支持 .json 地图文件"。

**C4. 用词不当**
- "活跃节点已达 30 个,请打开「整理地图」后再继续**扩张**"(`app.html:2320`)——"扩张"非中文习惯用词,建议"扩展"或"请先整理再继续添加"。
- "地图已更新(**外部修改**)"(2406 行)——系统视角词,建议"Agent 或其他程序更新了地图,已自动刷新"。

**C5. 面板标签"语义"偏术语**(`app.html:1096`)
- 下面是"目标/问题/结果"三选一,标签叫"语义"费解。建议"类别"或"性质"。

**C6. 整理预览的"当前位置"含混**(`app.html:1233-1235`)
- "当前位置 X(推测)"——"当前位置"易理解为视图位置,实为"当前节点";"推测"单字突兀。
- 建议:"当前节点 X(按记录推断)"。

**C7. 原始英文报错直出,无解释无出路**
- "导入失败:" + e.message(2431/2451)、"没能打开文件夹:" + e.message(2339)——JSON 解析错误会是英文 "Unexpected token…",违反"错误须解释+给出路"。
- 建议:兜底改为"导入失败:文件不是有效的 map.json。请检查文件来源,或重新导出一份再试。"

### P2 可访问性(技能可访问性准则)

**D1. 图标按钮只有 `title`,缺 `aria-label`**
- 工具栏五工具、项目菜单、缩放/撤销/重做、悬浮删除按钮等均以 `title` 标注。读屏器对 `title` 的播报不稳定。
- 建议:全部补 `aria-label`(可复用 title 文案)。

**D2. toast 与工具提示无 `aria-live`**
- `#toast`、`#tool-hint`(`app.html:453-454`)的状态变化读屏器不播报。建议加 `aria-live="polite"`。

**D3. 便签(标注)元素无可访问名称**
- `.ann` 只有文本内容尚可,但无 role;可接受,优先级低。

### P2 微调(顺手改)

- "恢复整理前"按钮(`app.html:441`)→"恢复到整理前"更顺。
- "正在检测 Agent / 读取中"(415 行)——"读取中"含义模糊,建议"检测中…"。
- 项目菜单用全角"？"字符当新手引导图标(1747 行)——与其它 SVG 图标不统一。
- 落地页 hero"人机协作 变得简单"中间空格在 `<title>`(layout.tsx:12)里也出现,建议标题用"人机协作,变得简单"或去空格。
- "已取消"(1757 行)建议"已取消选择"。
- 整理 meta"节点 30→30"无变化时仍显示,建议无变化的项隐藏,提升可扫描性。

## 六、结论

产品文案的整体水准高于多数同类工具:后果式确认、顾虑预答、空状态引导、成功消息 reassure 都做得对。主要欠账集中在三处——**教程与实际交互的一处事实错误(A1)**、**两处过时菜单指引(A2)**、以及**全站半角/全角标点与"标注/便签"这类成批的一致性问题(B1/B2)**。P0 三项建议本迭代内修复;P1 标点与术语可一次性脚本化清理;P2 可访问性项在下次走查时补齐。
