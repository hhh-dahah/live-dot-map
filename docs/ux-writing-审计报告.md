> 审计日期：2026-08 · 审计范围：`app.html`（主产品画布）、`landing/`（当前落地页源码）、`agent-kit/index.html`（接入说明）、`landing.html`（旧版落地页，参考）、`index (2).html`（原型导航）。

## 2. 做得好的（保留，不要动）

- **空状态**：「从一张地图开始 / 这里还没有项目地图。选择项目后所有改动自动存进项目里的 map.json，Agent 与你读写同一份文件。」——正面邀请式标题 + 解释 + 行动指引，符合空状态模板。
- **新手引导**：「一张人和 Agent 共享的探索地图：节点写目的与结果，方案线记每次尝试，Agent 每次会话先读地图汇报全局，你只做判断。」——价值前置、第二人称、短句，示范级文案。
- **破坏性操作透明**：覆盖确认（`新建空白地图并覆盖当前 map.json?`）、更新确认（`发现新版本…已保存的内容不会丢失。是否现在更新？`）、归档按钮（`归档此方案（弱化显示，不删数据）`）——后果都说得清清楚楚。
- **多模态状态表达**：方案状态用「线型 + 颜色 + 文字」三重区分（绿实线/红虚线/灰点线 + 状态名），不依赖颜色单独传义，符合无障碍规范。
- **成功消息具体化**：`已保存`、`引用已复制，可直接粘贴给 Agent`——过去时 + 结果，干脆。
- **落地页**：`人机协作 变得简单`、`你的项目，你的记忆`、`判断权永远在人：评分你打，归档你确认。`——全程第二人称、动词开头、无空话。

## 3. 高优先级问题（P0：影响理解 / 一致性）

### 3.1 术语不统一：同一概念多套叫法

| 概念 | 出现过的叫法 | 出现位置 | 建议 |
|---|---|---|---|
| 地图存储位置 | **工作区** / **项目文件夹** / **项目** | 设置抽屉叫「工作区」「当前使用临时工作区」；toast 叫「已连接项目文件夹」；菜单叫「选择项目…」「打开项目文件夹」 | 统一为「**项目文件夹**」（toast 与菜单的主流说法），设置抽屉里的「工作区」同步改名 |
| 接入动作 | **接入** / **连接** | 设置抽屉内并存「接入当前 Agent」与「连接当前 Agent」两个按钮 | 「接入」= 完成 Agent 集成；「连接」= 文件夹直连。同一面板内两个动作都用「连接/接入」开头会混。建议按钮统一为「接入当前 Agent」，说明文字解释两种方式 |
| 节点 goal 类型 | **目的** / **目标** | 默认节点类型 `type:'目的'`；节点类型按钮显示「目标」；落地页说「目标与尝试」 | 统一为「**目标**」，默认节点类型同步改（或至少在面板里写明二者关系） |
| 方案成功状态 | **走通** / **成功** | 教程「绿=走通」；状态徽标与落地页用「成功」 | 正式文案统一「**成功**」（徽标、图例、落地页一致），教程可写「绿=成功（走通了）」保留口语感 |

> 技能标准原话：*"Same word means same thing throughout"*（Clear 维度）。上述四处是当前最大的 Clear 失分点。

### 3.2 双重否定句（Agent 接入面板）

**现状**：`连接后，地图和当前 Agent 使用同一份本地记忆；未连接时不会显示已连接。`

问题：「未连接时不会显示已连接」双重否定，读一遍要反应两秒。

**建议**：`连接后，地图和当前 Agent 使用同一份本地记忆。未连接时，状态栏显示「未连接」。`

### 3.3 错误消息拼接原始技术信息

**现状**（保存失败 toast）：
`保存失败:文件夹可能被移动或权限被收回(Error: ENOENT: no such file...)`

问题：前半句是标准错误文案（原因 + 恢复线索），后半直接拼接英文原始错误。技能要求错误消息讲人话、给恢复路径，技术细节不该进用户视野。

**建议**：
`保存失败。检查项目文件夹是否被移动、权限是否被收回，然后重试。`
（原始 error 只写 console / 状态栏次要位置。）

同类问题：`map.json 无法安全加载:` + 原始异常、`更新失败：` + 原始异常、`没能打开文件夹:` + 原始异常——统一处理为「人话 + 重试/恢复动作」，详情降级。

### 3.4 标点不统一（半角/全角混用）

抽查 18 处 toast/confirm 中大量出现半角逗号、分号、冒号、括号：

- `保存失败:文件夹可能被移动或权限被收回(...)`
- `文件夹直连需要 Chrome 或 Edge;也可以导出 map.json 交给 Agent`
- `当前浏览器不支持直读文件夹,请用导入/导出`
- `「xxx.md」不存在,创建它吗?`
- `已连接项目文件夹:` + 名称

**建议**：中文界面文案统一全角标点（，。：；（）？），并顺手统一「…」与「...」。落地页 `landing/` 已全部使用全角，以它为准。

## 4. 中优先级问题（P1：清晰度与口语化）

### 4.1 接入面板说明句太长

**现状**：`状态只反映当前实际连接；若需要确认，请回到当前 Agent 对话完成一次接入。`（约 28 字，条件句前置了次要信息）

**建议**：`连接状态仅供参考。需要确认时，回到当前 Agent 对话完成一次接入。`

### 4.2 「读取中」无宾语

**现状**：状态文字「读取中」与「正在检测 Agent」并列时信息不对称。

**建议**：「正在读取连接状态」。

### 4.3 损坏文件提示半系统话

**现状**：`map.json 读不懂(文件可能损坏),画布保持原样未改动`

「读不懂」口语化是优点，但「map.json」文件名 + 「保持原样未改动」冗余（「保持原样」已含「未改动」）。

**建议**：`地图文件无法读取，可能已损坏。画布保持原样。`（文件名移到次要说明）

### 4.4 恢复确认句有认知负担

**现状**：`恢复到最近一次整理前的地图？整理后的改动会保留在恢复记录中。`

「恢复记录」未定义，读者需要推断它的含义。

**建议**：`恢复到最近一次整理前？整理后的改动会保留，之后仍可恢复。`

### 4.5 创建文件确认句不自然

**现状**：`「xxx.md」不存在,创建它吗?`

**建议**：`还没有 xxx.md，要创建吗？`

### 4.6 兼容性提示动词含糊

**现状**：`文件夹直连需要 Chrome 或 Edge;也可以导出 map.json 交给 Agent`

**建议**（前置用户能做什么）：`请用 Chrome 或 Edge 连接项目文件夹；也可以导出 map.json 交给 Agent。`

### 4.7 菜单项「显示内部编号」

「内部」是系统视角。**建议**：「显示编号」。

### 4.8 教程第三条超长

**现状**：`连上项目文件夹后，所有改动自动写进 map.json；详情写在节点/方案挂的 Markdown 分片里。失败的、不再碰的方案可以归档——不删数据，只是淡出。`（约 55 字）

技能基准：指令 ≤20 词（中文约 20–25 字），可扫描分段。

**建议**拆成两句 + 列表感：
`连上项目文件夹后，改动自动存进 map.json，详情写在 Markdown 里。不用的方案可以归档——只是淡出，不删数据。`

## 5. 低优先级问题（P2：打磨）

- `app.html` 所有图标按钮目前只有 `title` 悬停提示，**没有 `aria-label`**（无障碍规范：键盘与读屏需要显式标签）。建议 SVG 按钮补 `aria-label`（文案同 title）。
- `agent-kit/index.html` 全文半角标点 + 长句（`剩下全自动:下载画布到 ~/.live-dot-map/、建桌面快捷方式、注入协议、初始化地图、拉起画布。已有记录文件也会一并迁移成地图草稿,你在画布上审核。`）——统一全角并断句。
- 落地页页脚列头 `Explore / Product / Contact` 为英文，与全中文页面混用——改中文（`探索 / 产品 / 联系`）或直接去掉列头。
- 旧版 `landing.html` 与 `landing/` 并存维护两套文案（隐喻「行车记录仪」、半角标点、`演示 GIF 待补充` 占位）。既然已不发布，建议删除或标注 deprecated，避免后续误改。
- Toast「已创建 .live-dot-map/map.json 并连接:」把技术路径放在句首——建议 `已创建地图并连接项目文件夹：xxx`，路径放次要。
- 「当前地图已就绪，可在当前 Agent 对话继续协作」与「当前协作已就绪」并存——保留一个说法。
- `index (2).html` 为开发导航页，若保留建议加一行「开发用」标注。

## 6. 无障碍专项（按 accessibility-guidelines.md 核对）

| 检查项 | 状态 |
|---|---|
| 交互元素有描述性标签 | ⚠️ 图标按钮仅 `title`，缺 `aria-label`（P2） |
| 链接/按钮描述目的地 | ✅ `打开画布`、`接入说明`、`一键接入 Agent` |
| 错误消息具体可行动 | ⚠️ 部分 toast 拼接原始错误（P0-3.3） |
| 颜色不是唯一表义手段 | ✅ 方案状态 = 线型+颜色+文字三重编码 |
| 状态有文字而非仅图标 | ✅ `已保存`、`走通/失败/待验证` 均有文字 |
| 表单标签可见 | ✅ 评分框有可见说明 `0–100，留空即未评` |
| 图标 alt/aria-hidden | ✅ 装饰性图标均 `aria-hidden="true"`；落地页截图 alt 均有中文描述 |
| 句子长度（关键信息 ≤14 词） | ⚠️ 接入面板说明句、教程长句超标（P1） |

## 7. 优先修复清单（建议顺序）

1. **P0-3.1 术语统一**（工作区→项目文件夹、目标/目的、走通/成功、接入/连接）——改动小、收益最大，一次全文替换 + 面板改词。
2. **P0-3.3 错误消息去技术化**——给 toast 封装统一的「人话 + 重试」模板。
3. **P0-3.2 / 3.4 双重否定句改写 + 全角标点**——批量格式化一遍 toast/confirm 字符串。
4. **P1 各条逐句改写**（4.1–4.8，均有现成建议文案）。
5. **P2 打磨**：aria-label 补齐、旧版 landing.html 处置、页脚列头中文化。
