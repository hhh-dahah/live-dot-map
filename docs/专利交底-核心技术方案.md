# 专利申请技术交底：人机共享记忆的分层智能索引与上下文按需下探方法

> 用途：专利代理撰写正式申请文件的素材。本文按交底书习惯组织：技术领域 → 背景技术 → 要解决的技术问题 → 技术方案 → 实施方式 → 技术效果 → 创新点。所有量化数据均来自本产品真实实现与测试。

## 一、技术领域

本发明涉及人工智能与人机协同领域，具体涉及一种**人机共享的项目记忆管理系统**——人与 AI 助手在同一份图结构记忆上协作，系统以分层索引机制控制 AI 推理时的上下文成本，并保证双方写入的一致性。可用于：AI 编程助手的长程任务记忆、研发过程知识管理、多智能体共享工作记忆等场景。

## 二、背景技术（现有技术及其缺陷)

现有「AI 助手 + 项目记忆」类方案（向量数据库记忆、对话记录检索、RAG 上下文窗口等）普遍存在以下问题：

1. **信息载体覆盖不全（RAG 的普遍局限，最强分野）**：现有 RAG / 向量库方案几乎全部以**文本为中心**——嵌入、召回、注入上下文的都是文本片段；**图片、表格、图表、设计稿、专业文档（Word/PDF/Excel）等非文本信息要么被丢弃，要么被强行 OCR/转文本造成信息保真度损失**。而真实人机协作场景中，关键证据常常以原始文件格式存在——**图片就是图片、Word 就是 Word**，脱离原始载体即丢失信息；且这些原始文件往往由人手工协作产生，是 RAG 体系根本覆盖不到的盲区。
2. **上下文成本不可控**：多数方案把记忆内容（对话历史/文档全文/向量片段）成批注入模型上下文。记忆规模增长时，单轮推理的上下文占用线性膨胀，既超窗口上限又稀释重点信息（token 成本失控）。
3. **检索即全量扫描**：无索引或索引与正文未分离时，每次查询都需把全部记忆文件读入内存做相似度/关键词匹配，机器 IO 与内存随记忆量增长，规模不可扩展。
4. **检索不可解释**：向量检索（Embedding）召回结果无法说明「为什么是这条」，用户难以验证与纠偏；且引入外部模型服务违背本地优先、零依赖部署约束。
5. **人类输入丢失**：人与 AI 共享同一份记忆时，人类通过正文/文档写入的关键信息没有「未读信号」——AI 只能靠关键词碰巧命中，信息易被忽略；AI 也缺少「已读确认」机制，无法区分「看过了」和「没看过」。
6. **双写不一致**：人与 AI 同时修改同一记忆对象时，静默覆盖会造成数据丢失；无原子提交与冲突保护的方案存在崩溃丢数据风险。

## 三、要解决的技术问题

提供一种**分层记忆索引与按需下探**的方法，使 AI 助手在共享记忆系统中的单轮推理上下文成本与记忆总量解耦（近乎常数级），同时保证：索引与真实内容永远一致（人机双写环境下）、人类任意位置输入不被 AI 遗漏、所有召回可解释、所有写入原子且幂等、**任意格式的记忆对象以原始载体完整保真地可达**（不因限于文本而丢失图片/文档等关键证据）。

## 四、技术方案（核心技术思想)

### 4.1 总体架构：四级分层记忆

将「一份记忆」按粒度与访问频率分成四层，层间以路径引用关联：

```
第 1 层  结构化索引（图形脑图）
         人机共读的单一事实源：节点/路线/方案线/标注的结构、状态、布局。
         小（KB 级），随上下文全量携带 → "全局观"。

第 2 层  卡片索引（摘要 + 指纹）
         为每个正文文件登记【标题 + 前 N 字摘要 + 指纹(mtime/size/etag) + 附件清单】，
         不存全文。检索仅在这一层进行 → "智能索引"。

第 3 层  详情内容（Markdown 正文与补充文件）
         按对象目录存放；仅在命中时被下探读取 → "按需下探"。

第 4 层  资产文件（图片/PDF/Word/视频等任意格式，对象资料包）
         每一个记忆对象对应一个「资料包目录」，目录内可容纳**任意格式**的附件；
         Markdown 是人与 AI 共通的可读入口，通过路径关联目录内所有文件。
         一律以"路径 + 元数据"契约暴露，不搬运二进制；读取能力由消费方
         （本地 AI 进程/远程代理/人类）自备 —— 只要能读，信息就不丢，格式保真。→ "路径化下探"。
```

层级访问规则（可概括为一句核心思想）：**给 AI 的上下文只包含第 1 层全量 + 第 2 层命中摘要 + 路径，第 3/4 层进上下文必须以工具调用显式下探为前提。**

### 4.2 卡片索引的生成与维护（人机双写一致性）

- **生成**：任何正文文件的构建路径（创建对象、保存文档）完成后，同步为对象生成/刷新卡片：提取首标题与前 N 字摘要（示例 N=300）、计算内容哈希与文件指纹、枚举对象目录附件清单；索引以单个 JSON 文件原子写盘（`.bridge/md-index.json`）。
- **校验（廉价指纹）**：查询时对每张卡只做一次 lstat，比较 mtime+size；**一致→直接用卡片摘要（零全文读取）；不一致→仅重读该文件并刷新单卡**。
- **双写刷新覆盖全部写路径**：人类经应用保存、AI 经工具写入、文件改名、归档恢复、附件增删、对象创建——所有写路径统一在提交成功后触发单对象卡片刷新。
- **绕桥修改自愈**：用户用外部编辑器直接改文件（绕过系统）时，指纹失效机制在下次查询自动发现并只重读该文件，索引不会长期失真。
- **降级安全**：索引文件损坏/缺失时自动按需重建；不会被陈旧索引阻塞读取。
- 实测统计（500 对象规模压测）：第二次查询全文读取次数 = 0；外部改动 1 个文件后查询全文读取次数 = 1；首次建索引为一次性全量（≈对象数）。

### 4.3 上下文智能降载（按需下探）

- 每轮上下文固定携带：第 1 层结构化全集（KB 级）+ 第 2 层卡片检索结果（query 命中或最近书写兜底，上限 K 条，示例 K=6，仅摘要）+ 路径。
- 全文（第 3 层）与资产（第 4 层）均不进入上下文；AI 判断需要细节时，通过工具按路径定向读取（定向读正文 / 返回路径元数据），读取粒度=单个对象，成本=常数。
- 效果：单轮上下文体积与记忆总量解耦；模型 token 消耗、桥端 IO、内存占用三者同时受控。

### 4.4 人类输入信号闭环（任何位置的新信息不被遗漏）

- 人类在正文中的每次保存（应用内保存，可区别于 AI 写入）追加一条**未确认记录**（追加式日志，含路径/指纹/摘要，崩溃安全）。
- AI 每次会话上下文的「人类新输入列表」由两部分合并：结构标注（attention=new）+ 未确认正文写入（id=md:<路径>），二者并列呈现、同样必读。
- AI 引用后经确认接口应答，记录转为已确认不再重复提醒；同一对象再次被人类修改保存则重新亮起。
- 闭环保证：「写入时打标记 → 读取时必列 → 确认后不再打扰」，与输入载体（画布标注/文档正文）无关。

### 4.5 数据一致性与崩溃安全（可并入已有公知做法作为配套）

- 固定提交序：WAL 落盘并 fsync → 命令 reducer 应用 → 全量校验 → 临时文件 fsync → 原子替换 → 目录 fsync → 返回新版本号。
- 版本冲突不静默合并：基线落后且字段重叠返回 409，双方数据保留，由人/AI 显式读后合并。
- 命令按 commandId 幂等；外部损坏文件移入隔离区，不污染当前视图；崩溃后启动重放未完成 WAL（RPO=0）。

## 五、实施方式（关键流程示例）

**流程 1：保存即建卡（写入路径）**
1. 收到正文保存请求（人类/应用）→ 校验 → 原子写入正文文件；
2. 读回文件，计算标题/摘要/指纹；
3. 合并更新卡片索引并原子写盘；
4. 追加人类输入未确认记录；
5. 向客户端返回新内容与 etag。

**流程 2：查询下探（读取路径）**
1. AI 请求上下文与检索词；
2. 读卡片索引（单文件）→ 对摘要场做检索打分（保留可解释理由）；
3. 逐对象 lstat 校验指纹；失效者现场重读并刷新该卡；
4. 返回：结构化全集 + 命中摘要（≤K 条、含理由）+ 未确认人类输入 + 路径；
5. AI 需要细节 → 定向读正文工具 / 资产路径工具。

## 六、技术效果

| 指标 | 效果（实测） |
| --- | --- |
| AI 每轮上下文体积 | 与记忆总量解耦（500 对象 0 全文读取） |
| 检索成本 | 常数级（1 个索引文件 + N 次 lstat） |
| 索引一致性 | 任何写路径/绕桥修改后，一次查询内自愈 |
| 人类输入丢失率 | 结构上消除（双通道未读信号 + 确认闭环） |
| 召回可解释性 | 每次召回附确定性理由 |
| 信息载体覆盖 | 任意格式附件以原始载体保真可达（资料包+路径），不限于文本 |
| 写入安全 | RPO=0、409 冲突保留、commandId 幂等 |
| 部署约束 | 零外部依赖、本地优先、文件即数据库 |

## 七、创新点（与现有技术的区别，按新颖性强度排序）

1. **对象资料包为记忆单元 + 路径化下探（跨格式完整保真，最强分野）**：以「资料包目录」为单位组织**任意格式**的附件（图片/Word/PDF/Excel/多媒体），Markdown 为共通入口、路径为纽带——不同于 RAG 仅文本召回/强行转文本的信息损失；只要读取方具备对应格式的读取能力，原始载体即可完整可达，**图片就是图片、Word 就是 Word**，信息不因检索机制而丢失。
2. **「图概要 + 卡片摘要 + 正文 + 资产」四级分层与上下文按需下探**：区别于 RAG/向量库把内容压平注入上下文；区别于全文内存检索的无索引方案。AI 上下文只含概要、命中摘要与路径，全文/资产必须显式下探——上下文成本与记忆总量解耦。
3. **指纹驱动的惰性自愈索引**：用 lstat 廉价指纹做索引新鲜度判定，而非每次全量重建或依赖外部变更通知；双写与绕桥修改统一自愈，一次查询内收敛。
4. **人类正文输入信号闭环（md 未读信号 + AI 已读确认）**：把「人对系统的重要输入」从依赖检索碰命中的偶然行为，提升为结构保证；与结构标注并列、同样必读。
5. **可解释确定性检索**：在不引入 embedding/外部模型的前提下实现可控召回成本，符合本地优先与零依赖约束。
